# WordShift - Claude Code Context

A word puzzle game where players shift letters between words to form valid English words. What begins as a bright, candy-colored experience with adorable animal companions gradually descends into cosmic horror — the animals are revealed to be members of a cult, and every puzzle the player solves brings them closer to summoning a dark entity.

## Quick Commands

```bash
cd mobile
npx expo start           # Start dev server (scan QR with Expo Go)
npx expo start --clear   # Clear cache and start
npm run typecheck        # tsc --noEmit
npm run lint             # ESLint 9 flat config (eslint-config-expo)
npm run generate:assets  # Regenerate icons/splash/notification icon/SFX (pure Node)
```

## Testing

- **Run all tests**: `cd mobile && npm test -- --no-coverage`
- **Run a single test file**: `cd mobile && npm test -- --no-coverage --testPathPattern=<filename>`
- **Run tests for changed files only**: `cd mobile && npm test -- --no-coverage --changedSince=main`
- Do NOT use `npx jest` directly — it does not find the local install and triggers a full remote download + deprecated dependency warnings every time. Always use `npm test` which routes through the locally installed jest.
- `npm install` IS allowed in this environment. Fresh containers may start without `node_modules`; run `cd mobile && npm install` (or `npm ci`) once at the start of a session before running tests/typecheck/lint. Prefer `npm ci` when `package-lock.json` is present and unchanged.
- The full suite has ~111 suites (thousands of tests), expected green (counts drift as features land — don't treat the numbers as load-bearing). **Prefer running only the relevant test file(s)** rather than the full suite unless explicitly asked to run everything.

## Narrative Vision

**The core conceit**: The player is unknowingly participating in a ritual. Every puzzle solved is an incantation. The animal "friends" aren't just getting philosophical — they're preparing for something. The house isn't just a home — it's a temple being constructed, room by room, to house something ancient.

**The tone shift must be gradual and earned.** The game should feel genuinely delightful for the first 25+ puzzles. Players should *like* these animals. The betrayal of that warmth is the entire point. When Fox says "The fire grows cold... but something else burns," it should land because the player remembers when Fox just wanted to tell them about cozy blankets.

**Everything reflects the transition:**
- **Puzzle words**: Shift from FUN/SPARK/TIGER → VOID/DOOM/ABYSS/RITUAL
- **Background visuals**: Bright candy purple → near-black with crimson accents
- **Floating particles**: Sparkles and stars → dim, dying embers
- **Victory text**: "PERFECT!" → "WHY DOES IT MATTER?" (plus ritual echo showing completed word chain)
- **Words offered counter**: Simple stat → "N words offered to the arrangement"
- **Move messages**: "Delicious!" → "The void accepts."
- **Confetti**: Vibrant rainbow → muted, dark colors
- **Hints**: "Move 'R' — think WARM!" → "If it matters, 'R' — see VOID."
- **Home screen**: Sunny day, happy clouds → storm sky, shadow figure looming
- **Animal sprites**: Cute idle poses → robed cult figures
- **Letter tiles**: Bouncy, fast wobble → heavy, ponderous movement with trailing glow
- **Shadow figure**: Invisible (Phase 0-2) → faint silhouette (Phase 3, opacity 0.18) → full looming presence with crimson eyes (Phase 4, 0.5) → settled (Phase 5, 0.35). `ShadowFigure` in HouseWorld.tsx renders `shadow_figure.png` behind the house with a slow breathing loop (native driver, reduced-motion aware)
- **Sound**: a 42-file audio pack (warm additive-synth chimes with a rising combo ladder, a full dark mirror set from Phase 3, and bright/dusk/dark ambient music beds that corrupt with the descent)

**Key narrative rules:**
1. Never break the fourth wall. The animals don't know they're in a game.
2. The darkness should feel *earned*, not sudden. Each phase is a gradual shift.
3. Phase 4 animals aren't "evil" — they're reverent, serene, certain. That's what makes it unsettling.
4. The player should feel complicit. "You solved the puzzle. You brought us closer."
5. Visual changes should slightly precede dialogue revelations — the player should *feel* something is off before they're told.
6. The shadow_figure.png entity is never named, never explained. It just *is*.
7. **Never reveal the phase system to the player.** No "Phase 2/5" labels, no progress bars toward phase transitions. The player should experience the shift organically through visuals, dialogue, and tone — never through a UI label telling them what stage they're in.

**Phase narrative arc:**
- **Phase 0 (Bright Days)**: Pure joy. Cute animals, candy colors, fun words. The trap is set.
- **Phase 1 (Curious Thoughts)**: Animals start wondering about the nature of things. Subtle philosophical undertones.
- **Phase 2 (Deeper Questions)**: Isolation creeps in. Animals question reality, impermanence. Words shift toward emptiness. The background noticeably darkens.
- **Phase 3 (Growing Shadows)**: Overt dread. Animals speak of endings, purpose, something approaching. The puzzle screen feels cold. Victory feels hollow.
- **Phase 4 (The Horizon)**: The cult is revealed. Animals speak of "the arrangement," "the pattern," "what comes through." Robed sprites. Storm sky. The shadow figure appears. Every puzzle solved is explicitly framed as part of the summoning.
- **Phase 5 (Post-Revelation)**: After the final puzzle + house completion. Terrible peace. Animals are serene, not dreadful. The shadow has settled. Victory text: "The pattern continues."

## Game Mechanics

### Core Puzzle Loop
1. Player sees a chain of words (3-5 rows depending on difficulty)
2. Pick a letter from current word — word shrinks by 1 letter
3. Drop letter into next word — word grows by 1 letter
4. Both resulting words must be valid English words
5. Progress through all rows to win

**Drag z-order (contract):** the dragged tile is a floating copy rendered IN PLACE inside `DraggableTile`, so it escapes its row only if that row out-ranks its siblings — and paint order among rows is decided by their OUTERMOST elements. The drag lift therefore lives on Row's board-serve entrance wrapper (`serveWrapperDragging`, zIndex + a matching `elevation` for Android), never on an inner wrapper. Pinned by `puzzleFeelContracts.test.ts`.

**Move feedback (game feel):** a valid move plays a catch bounce + star burst with escalated haptics (drag-drop `hapticHeavy()` vs tap `hapticMedium()`) and `soundValidMove()`; an **invalid drop** plays `hapticError()` + `soundInvalidMove()` + the target-row error shake (so rejection is felt at the hand, not just shown on the board — `App.tsx` `handleSlotPress` result-`null` path). **Intra-puzzle escalation:** consecutive clean moves on a board ramp the move message via `getComboMoveMessage(streak, phase)` (phase-aware, tiered at streak 2/3/4+); the streak (`cleanMoveStreakRef` in `usePuzzleGame`) resets on an invalid attempt, undo, reverse-midpoint, or new board. **Double-shift `drop1`** (half a move, no `formedWord`) gets a soft "click into place" (`hapticSelection` + `soundTap` + catch bounce), reserving the star-burst celebration for completed words. A drag released **off any row** (Y-bounds reject) now gives feedback — `hapticSelection()` + a phase-aware `getDragMissMessage(phase)` — instead of silently vanishing. **Tap-path arrival**: a tap-committed move plays an arrival settle on the moved tile (`arrivalMoveId`/`arrivalDirection` from `usePuzzleGame` → LetterTile scale/translate spring, phase-aware, reduced-motion aware); drag keeps its own collapse feedback, and autosave restore never replays an arrival. **Cross-row flight (the "flying ghost", audit F1, shipped 2026-08-31)**: the same tap commit also flies a ghost copy of the moved tile from the source tile's position into the landing slot — `ArrivalMark` carries optional flight endpoints (`flightChar`/`sourceRowIndex`/`sourceLetterIndex`/`sourceWordLength`/`targetWordLength`, absent on drag/drop1/undo/restore), and App resolves them to window coords (X analytic via `standardLetterCenterOffset` × boardScale; Y measured from the registered row nodes, stable across a commit) and renders `components/puzzle/FlyingTileGhost` (real LetterTile chrome, native driver, `TILE_FLIGHT_MS` 260ms with a `TILE_FLIGHT_LIFT_DP` bow, fades into the settle as it lands). Reduced-motion/low-tier devices skip the flight; the settle is their feedback. **Inactive tiles acknowledge taps** (pre-launch fix): tiles with no action available — completed rows, future rows, and the target row before a letter is selected — mount a feedback-only touchable instead of bare content (`onInactivePress`, threaded App → Row → LetterTile on non-source rows only). A tap fires exactly two things: `hapticSelection()` (App's `handleInactiveTilePress`, stable identity, haptic-only) and a subtle native-driver scale pulse on the tile (dip to 0.94 over ~70ms, spring back; skipped under reducedMotion while the haptic survives). No message, no sound, ZERO game-state effects; the active-row locked shake+message and the inter-slot pulse paths always take precedence, drag is untouched, and the touchable deliberately carries no accessibility role (screen readers are never promised an action). Pinned by `puzzleFeelContracts.test.ts`.

### Word Preview Mechanic
When a letter is selected, ghost previews show what word would form at each slot position. **Validity GRADING is difficulty-gated (v1.3.0 verb redesign)**: `previewValidityVisible` in `usePuzzleGame.ts` is true ONLY on EASY (any variant except blind) and in the double_shift variant at any difficulty (its intermediate non-word state needs the guidance). When visible: valid words green with a "✓ " prefix, invalid red/dimmed with "✗ " (never color alone); a slot shows ✓ only when **both** resulting words are valid (the preview ANDs source-word validity). When hidden (MEDIUM+ standard/reverse/speed, the daily, shared-challenge boards): the ghost word renders in one neutral dimmed ink with no ✓/✗ and no valid/invalid styling — the player judges the word, which is where the skill now lives (pre-redesign, 78-83% of steps had exactly one legal move and the UI graded it for free). `isValid` is still computed internally (look-ahead/blind judgment/snapping need it); the flag controls PRESENTATION only. Screen readers announce the formed word always, the verdict only when grading is shown (no a11y leak). The drag valid-slot snapping tell follows the same rule; hidden-validity boards snap to the geometrically nearest slot. **Preview-grading transition** (`resolvePreviewGradingMode` in `usePuzzleGame.ts` → `PreviewGradingMode` = `'graded' | 'neutral' | 'hidden'`, exposed as `previewGradingMode`): validity is fully graded on EVERY board (any difficulty) until `PREVIEW_GRADING_FULL_LIMIT` (12) total puzzles are solved (so the tutorial's ✓/✗ teaching never hands off cold to ungraded MEDIUM on the first free board). From puzzle 12 on, the otherwise-ungraded boards (MEDIUM+ standard/reverse/speed, daily, shared-challenge) go permanently **neutral** — the marks step back for good. The transition is **one-way**: `previewValidityVisible = previewGradingMode === 'graded'`, so a neutral board never shows the ✓/✗ and an invalid attempt does NOT bring them back (the old 'rescue' tier that resurrected grading after a mistake was removed — it read as a glitch). A one-time in-world graduation beat (`getPreviewGraduationTitle`/`getPreviewGraduationMessage`/`getPreviewGraduationConfirm`, key `wordshift_preview_graduation_seen_v2`, device-local) fires on the FIRST genuinely ungraded board, so the player is always told when the marks step back (closes the old silent-stop gap). It is delivered as an **UNMISSABLE blocking cottage card** (the `showGameAlert` host covers the board until the player acknowledges it) rather than the original fading toast — a "the rules just changed" moment must not race the board-start line or blink past unread (App.tsx gates it on `previewGradingMode === 'neutral'` so a hidden-preview rescue board can't consume it early). The flag commits on **acknowledgment** (the card's button), never at decision time, and the key is **versioned (`_v2`)** because the original toast delivery marked the old key seen before showing and the post-phase-transition moment routinely ate the toast — observed on-device: checks went neutral with no message, beat burned invisibly; the rename grants every such device one guaranteed showing of the card. Previews are suppressed ENTIRELY (`'hidden'`) only in **Blind Offering**.

Its vocabulary leans **"uncommon-but-fair"** via a MILD generator rarity lean (`rarityLean=1`, see localGenerator) under a fair featured ceiling (rank ~0.85, excluding the obscure validity-only inflection tail). Rewards: `AMBER_REWARDS.EXPERT` 28, first-completion +75, surprise 20, speed timer 44s, 1 undo in Challenge; counts as HARD-tier for narrative acceleration (`amberCurrency`). DifficultyMenu renders it as a gated (🔒) row until earned. All 6+ letter rows render **compact tiles** (Row.tsx `compactTiles = wordLength >= 6`), so the 7-tile transient row fits. Banks: `puzzleBankExpert.ts` (standard 6L) + `puzzleBankDoubleShiftExpert.ts` (double 5L/7-row) + `puzzleBankReverseExpert.ts` (**reverse 6L, 200 boards — added after an hours-long gated rare/reverse run; fair 6-letter reverse-solvable chains are scarce but reachable, so this bank is smaller than the E/M/MP/H reverse banks and recycling covers the size**), all routed via `getBankKey` (`reverse_expert` now IN the registry → served from the bank, no longer on-device).

### Puzzle Variant Modes (`puzzleVariety.ts`)

Player-selected from the setup menu. Persisted as preferred variant.

- **Reverse Shift** (unlock: 10 puzzles — moved from 8 pre-launch so the reverse intro waits two boards past the daily unlock (8) and the mandatory first harvest (win 9) instead of stacking on that one-time-beat cluster; `puzzleVariety.test.ts` pins the gate clears `DAILY_CHALLENGE_UNLOCK_PUZZLES + 1`): Play down then back up. Forward-pass letters stay locked (cumulative locking). All served from pre-generated banks with `reverseSolution` for hints. The descent→ascent **midpoint** returns `reverseMidpoint: true` so App fires a celebratory `hapticSuccess()` (the return leg reads as a second act). If on-device generation can't produce a reverse-solvable puzzle and silently downgrades to standard, `startNewGame` now surfaces a phase-aware notice instead of swapping styles unannounced.
- **Double Shift** (unlock: 25 puzzles): Move 2 letters per step. 4-phase input cycle: `pick1 → drop1 → pick2 → drop2`. All words are 5 letters (W=5). Difficulty by row count: EASY=3, MEDIUM=4, MEDIUM_PLUS=5, HARD=6. 1.65x amber multiplier. The first drop (`drop1`) returns a non-null result with **no `formedWord`**, so App gives positive drop feedback (catch bounce + haptic) while skipping dread tracking — it does not fall through to the "invalid drop" error path. The `drop1` slot previews use a **look-ahead** (`canCompleteDoubleShift`): a slot shows ✓ only when some second move from there yields two valid words, so the first drop is guided, not guesswork. Stuck detection runs after each completed step via `hasAnyValidDoubleShiftMove` (the two-letter analogue of `hasAnyValidMove`), surfacing the recovery panel if the row is trapped. **Undo:** mid-step undos (before the step completes) are always free, even in Challenge mode. In **Challenge** mode, undoing a *completed* step reverts BOTH drops atomically for ONE undo charge (`handleUndo` detects the paired deltas by shared `activeRowIndexBefore`) — never a half-revert that strands the first drop or burns two charges; standard mode keeps its granular per-drop undo.
- **Speed Shift** — NOT a variant. It is the fourth composable **MODIFIER** (`speedMode`, gate `SPEED_TOGGLE_UNLOCK_PUZZLES` 55): a clock laid over whatever style is already selected, so it stacks with Challenge/Blind/Lexicon AND rides standard, reverse or double shift. `'speed'` was removed from BOTH `PuzzleVariant` and `VariantModifier` (leaving it in the modifier union would have kept every `hasVariantModifier(v,'speed')` call type-checking while silently returning false forever). It changes NO board: bank routing is untouched, so every (style × difficulty × lexicon) bank is reachable under the clock with no new bank work, and the old `rowOverride: 3` was deleted (it only ever reached the on-device generator — speed boards have been bank-served at full standard length for a long time). The clock is `getSpeedTimeLimit(difficulty, variant)` = `SPEED_TIME_LIMITS[difficulty] × SPEED_STYLE_TIME_MULTIPLIER[variant]` (standard 1.0 / reverse 1.9 / double_shift 1.6 — an EXPERT double shift is a 7-row two-letter board and the bare 44s would be unwinnable). Amber is `SPEED_AMBER_MULTIPLIER` (1.34, unchanged from the old variant rate), applied like Lexicon's inside `awardPuzzleAmber`, itemized as `speedBonus`, **reward-only — never phase progress**. Lifetime wins moved to `progress.speedWins`; `getVariantWinStats` also reads the legacy `variantWins.speed`, and **dataMigration v5** folds it forward and retires a stored `'speed'` style preference. A board autosaved by the pre-conversion build is coerced on restore (`currentVariant: 'speed'` → standard + `speedMode` on) since `puzzleSaveState` carries no schema version. Forced OFF on the finale (a countdown over a played ending breaks the beat), the daily and shared boards; speed boards are excluded from the +1-row extension (a longer chain on a shorter clock) and from house asks. Quests use a dedicated `speed_wins` type (a `variant_wins` quest keyed to a nonexistent variant would be filtered out of every draw forever). Timed run with difficulty-aware base timers (EASY 65s → HARD 48s). **Escalation ladder**: each consecutive speed win increments App-level `speedRound`, trimming the next clock by `SPEED_ESCALATION_STEP_SEC` (5s, floored at `SPEED_ESCALATION_MIN_SEC` = 30s) so a streak keeps tightening instead of letting skilled players idle. A "🔥 Round N" indicator appears under the timer once `speedRound > 0`. The ladder resets on any fresh run (Play, variant/difficulty/challenge switch, Home) and on the Time's-Up overlay exits (Try Again / Home) — **not** on time-up itself, since a rescue may continue the run; only **Next Level** continues it. The clock **pauses while the app is backgrounded** (AppState listener in `useSpeedTimer`) and resumes from the saved remaining seconds after a relaunch (`speedTimeRemainingSec` in autosave; legacy `speedTimerExpireAt` still restores as a fallback). Time-up sets `GameState.GAME_OVER` (warning haptic + sound) and shows a **"Time's Up" overlay** in App.tsx with the phase-aware `getSpeedTimeUpMessage(phase)`, a **once-per-board rewarded rescue** (`RewardedAdButton`, placement `speed_rescue`, +30s — `resumeSpeedAfterRescue` flips GAME_OVER→PLAYING and the timer effect restarts the clock; `speedRound` deliberately survives), and two CTAs: **Try Again** (new puzzle) and **Home**. `GAME_OVER` is set *only* on speed time-up.

### Late-Game Puzzle Extension (+1 row)
The mirror of the curated early ramp at the top end: once the player has solved `PUZZLE_EXTENSION_UNLOCK_PUZZLES` (70, `services/puzzleExtension.ts`), **every standard board gains one extra row**. `extendStandardPuzzle(config)` appends one canonical standard-rule move using only synchronous dictionary lookups (no re-search), so a late EASY board becomes 4 rows, MEDIUM/MEDIUM_PLUS 5, HARD 6. Applied on **both** delivery paths: bank selection filters to boards whose stored solution can be safely extended (`getCachedStandardExtension`, recycling within the extendable subset) and generation extends the served board, each with a `getGuaranteedExtendedStandardFallback(difficulty)` safety net when a specific board can't be extended. **Excluded:** reverse and double-shift (`extendStandardPuzzle` early-returns on `reverseSolution`/`isDoubleShift`), the Daily and shared-challenge boards (their own start paths never route through it), the finale board, and Unbroken Weave (extension is skipped when `requestedUnbrokenWeave`, so the one-use-per-letter eligibility set is never perturbed). Solvability is preserved by construction (the appended step is a validated real move). **Branching-preferring append (Depth Levers Pass):** the extension scan prefers a valid append whose FINAL step is not forced — `countFinalStepOutcomes` checks that 2+ distinct valid outcome words remain on the appended row (early-exits at 2), examining up to `MAX_PREFERRED_APPEND_ATTEMPTS` (40) valid appends before settling for the first valid one as fallback — so the +1 row keeps a real choice alive instead of ending every extended board on a single-move rail (sync dictionary lookups only, same order of work).

### House Asks (per-board constraint beat)
On **25%** (`HOUSE_ASK_CHANCE`) of eligible standard boards past **40** solves (`HOUSE_ASK_MIN_PUZZLES`, gameBalance — which also covers the curated early boards), the house quietly asks ONE small thing of the arrangement: a specific letter **must travel** (`'move'`) or **must be left untouched** (`'keep'`). `services/houseAsks.ts` is pure (derive/pick/evaluate, deterministic given rng); **App.tsx owns the roll, the badge, and the victory evaluation**. Both ask kinds are derived from the board's **stored solution**, so every ask is **satisfiable by construction** (replaying the stored route keeps either kind): `deriveHouseAskCandidates` collects 'move' candidates (unique solution-moved characters, step order) then 'keep' candidates (characters in a NON-final start row the solution never moves — a character whose sole presence is the final row is excluded, since final-row letters can't travel and "leave them be" would be hollow); `pickHouseAsk` draws uniformly. On multi-route boards the ask **selects between routes — which is the point** (it composes with the gated banks' guaranteed 2+ routes). Semantics are **letter-CHARACTER, never a specific tile**; `evaluateHouseAsk` judges the committed move history once, at the WON commit. **Kept:** +`HOUSE_ASK_REWARD_AMBER` (15) via `awardBonusAmber('house_ask')` (amber-only, NEVER phase progress) + a receipt-priority victory toast (`getHouseAskFulfilledMessage`). **Unkept: silence, forever** (soft-fail contract — cleared with no message; the house never scolds). Delivery: the ask rolls once per fresh board (keyed on board identity, gates read at fire time), speaks via `getHouseAskLine(phase, kind, letter)` (queued ~2.2s behind a board-start greeting rather than clobbering it), and shows a standing **🏠 badge with the letter** in the puzzle statsRow (same chrome as the variant badges; the full phase-aware ask line rides the accessibility label). **Never on:** the daily, shared-challenge boards, the finale board, Blind Offering, Unbroken Weave, non-standard variants (reverse/double/speed), during onboarding, or below the solve gate; a **restored autosave board never rolls** and a live ask does NOT survive autosave restore or leaving the puzzle screen (deliberate simplification — an interrupted board simply has no ask; suppress ref + committed-move guard in App).

### Star Rating
- **3 stars**: 0 hints, 0-1 invalid attempts
- **2 stars**: 1 hint OR 2-3 invalid attempts
- **1 star**: 2+ hints OR 4+ invalid attempts

The middle rung of the trial ladder: difficulty-aware undo limit (EASY/MEDIUM=2, MEDIUM_PLUS/HARD=1), no hints; previews follow the global validity-gating rule (graded on EASY only). 1.25x amber; counts 1.5x toward phase progression. ### Post-Launch Analysis Fixes (2026-07-24, closed testing)

An end-to-end analysis during Play closed testing found and fixed several defects; the topic sections are authoritative where numbers appear.
- **Endgame lockout (blocking)**: `markPostRevelation()` — the only route to Phase 5 — sat inside `if (houseComplete)`, and house completion costs **4,615 amber** on the unlock ladder while ~5,600 amber of cosmetics is ungated from solve 0. A slow-earning or cosmetics-first player was silently, permanently locked out of the ending. ### Unbroken Weave (Phase 5 mastery mode)

The **post-revelation apex** — a mastery pursuit that sits *beyond* the trial ladder and is reachable ONLY at the true endgame. `isUnbrokenWeaveAvailable(currentPhase, postRevelation)` (`services/unbrokenWeave.ts`) gates it to global **phase 5 AND the persisted `postRevelation` flag** (not merely a Phase-4 board that resolved to animal-phase 5). A 🧵 toggle appears in DifficultyMenu only when `showUnbrokenWeave && phase === 5 && !introMode`; `handleToggleUnbrokenWeave` in App flips `unbrokenWeaveMode` (mode is amber-only, never phase progress).

- **The one rule:** each moved letter *character* may cross the chain **exactly once** across the whole board. `usePuzzleGame` tracks a `spentLetterSet` (`isLetterSpent`/`addSpentLetter`/`removeSpentLetter` in unbrokenWeave.ts); a pick of an already-spent letter is refused with `getUnbrokenWeaveSpentLetterMessage`, and every committed move (and undo) adds/releases the letter. Look-ahead/stuck detection also filter out spent letters.
- **Board eligibility:** the mode forces a **standard** board and serves ONLY boards whose canonical solution moves all-unique single letters — `getUnbrokenWeaveEligibility(solution)` rejects `missing_solution`/`invalid_letter`/`double_letter_step`/`reused_letter`. Bank selection passes `unbrokenWeaveOnly` (filters to `isUnbrokenWeaveEligible` boards, recycles within that subset); generation validates the same way. If no eligible board can be produced (or the toggle is requested outside phase 5), `startNewGame` falls back to a normal board with `getUnbrokenWeaveUnavailableMessage` + `disableUnbrokenWeave` instead of a silent swap.
- **Undos:** free and unlimited (it runs as an ordinary standard-mode board — no challenge budget, no blind flag), and undoing releases the spent letter so the chain can be re-walked. Ordinary standard amber (no trial multiplier).
- **Reward is private mastery, not amber:** `recordUnbrokenWeaveVictory(difficulty, flawless)` advances the `UnbrokenWeaveMastery` ladder in `masteryRecords.ts` (cloud-synced under `wordshift_mastery`) — 6 ranks: **Unbroken Weave** (base) → **Thread Joined** (1 win) → **Fourfold Weave** (cleared on all 4 difficulties) → **Seamless Dark** (a flawless HARD) → **Loomkeeper** (10 flawless) → **Patternbound** (25 flawless). The VictoryModal shows the rank/title/next-objective + a rank-up line (`getUnbrokenWeaveRankUpLine`).
- **Intro & persistence:** a one-time Fox intro from HomeScreen (`hasSeenUnbrokenWeaveIntro`/`markUnbrokenWeaveIntroSeen` in amberCurrency, `getUnbrokenWeaveIntroLines`, `introContext: 'unbroken_weave_intro'`, flag `unbrokenWeaveIntroSeen` on home progress). `unbrokenWeaveMode` survives autosave in `SavedPuzzleState`. The finale board and curated early boards force it off.

### Daily Challenge
Deterministic seeded generation. **Board shape ramps across the week** (`getDailyRamp`, Mon→Sun, the Wordle/NYT pattern: Mon MEDIUM 4-letter/4-row → Tue-Wed MEDIUM_PLUS 5-letter → Thu HARD → Fri MEDIUM_PLUS breather → Sat HARD → Sun HARD 6-letter/5-row peak; deterministic by date so every player gets the same board and the leaderboard stays fair — **rewards still always count as HARD**). Streak tracking with a yesterday-only **free** continuation, now backed by a **freeze mercy**: a banked daily-streak freeze (one granted every `DAILY_FREE_FREEZE_INTERVAL_DAYS`=14, capped at 1) auto-forgives a single missed day instead of nuking a long streak — `recordDailyCompletion` consumes it and returns `streakSavedByFreeze` (App surfaces a "🛡️ your daily streak held" message); `getDailyStatus` exposes `streakFreezes`. Unlocked at **8 puzzles** or Phase 1+ (`DAILY_CHALLENGE_UNLOCK_PUZZLES` in `constants/gameBalance.ts` — aligned with the close of the pit auto-collect window, so the daily lands as a challenge, not a wall). A **one-time first-daily mercy** grants +`FIRST_DAILY_BONUS_HINTS` (2) free hints when the very first daily starts (`grantFirstDailyMercy` in dailyChallenge.ts, surfaced as a toast from `App.handleStartDaily`). One-time Fox intro.

**Entry point & wiring**: A `DailyChallengeCard` (📅) sits in the **HomeScreen header**, gated by `isDailyChallengeUnlocked()` and hidden during onboarding (shows a pulsing calendar when available, a check + stars + streak badge once done; a 🌕 badge on full-moon event days via `getEventBadgeLabel`). App-level `isPlayingDaily` state threads through `useAutosave` (tags the save with `isPlayingDaily`/`dailyDate`; a daily save is never restored as a normal puzzle), `recordVictory(..., isDaily=true)` (rewards always count as HARD), and the VictoryModal ("Daily Challenge Complete"). On full-moon event days the daily also pays a **+50% amber bonus** (`getEventDailyBonusAmber` → `awardBonusAmber(..., 'event_daily_bonus')` — bonus-only, never phase progress). Completions log a `daily_completed` event. `isPlayingDaily` resets on every non-daily start path (Play, variant/difficulty/challenge switch, Home, Next Level).

## App Architecture

### Custom Hooks

**`usePuzzleGame()`** — All puzzle state: rows, selected letter, game state, hints, validation, variant handling. Key methods: `initGame()`, `startNewGame()` (guarded by a monotonic `generationIdRef` — every `initGame` commit aborts if a newer call superseded it, so rapid Play/Next-Level taps or a mid-generation variant switch can't clobber a started board), `startDailyGame()` (Daily Challenge bypass path — standard board from seeded words, leaves difficulty pref intact), `startSharedChallengeGame(words)` (friend-challenge link path, validated), `handleLetterPress()`, `handleSlotPress()`, `handleHint()`, `handleUndo()`, `clearBoard()`. Returns `slotPreviews` for word preview mechanic. `handleHint()` also raises `hintHighlight` — the hinted tile + target slot glow on the board, reusing the tutorial-glow rendering (cleared on move/undo/new board; never restored from autosave) — and its off-solution fallback candidates filter through `isBoardSolvableFromState` (the lock-aware from-state analogue of `isChainSolvable`), so a hint never suggests a legal-but-stranding move. Tracks per-move `moveOutcomes` for the honest share grid, per-move **resonant-choice flags** (`collectDistinctOutcomeWords`/`isResonantChoice` — see Move Resonance; undo pops the flag), and raises `speedRescueSignal` from `resumeSpeedAfterRescue`. **Shared-challenge boards are amber-only**: `isSharedChallenge` threads into `recordVictory` → `awardPuzzleAmber({skipPhaseProgress: true})` (full amber, ZERO phase progress) with ritual energy forced to 0 — a friend link can never accelerate the descent; the provenance survives kill/restore via `isSharedChallenge` in `SavedPuzzleState`. After each committed move (non-double-shift), `hasAnyValidMove()` runs stuck detection and sets `isStuck` — **near-silent by product decision, with a v1.3.2 one-time mercy**: the ONLY consumer of `isStuck` is a ONE-TIME-EVER first-stuck notice in App.tsx (shows `getNoValidMovesMessage(phase)` once, behind the device-local flag `wordshift_first_stuck_seen` — deliberately NOT cloud-synced, a returning player on a new device may deserve the mercy once more); after that, stuck detection is fully silent again (no panel, no toast — discovering a dead-end and choosing Undo/Restart is part of the challenge; `appIntegration.test.ts` pins this exact contract). `getStuckPanelTitle()` remains in phaseNarrative but intentionally unused. `isStuck` resets on undo/restart/new board.

**`useGamePersistence()`** — Persistence: amber, stats, phases, streak. Key: `recordVictory()` returns VictoryData (includes `phaseTransitionPending`, `harvestedWords`, `pendingHarvest`, `firstCompletionBonus`). It enqueues ONLY the per-puzzle `amberResult.amount` into the harvest batch (the milestone/first-completion/streak-milestone windfalls are already balance-credited by `awardPuzzleAmber` — see Offering Pit Economy); `VictoryData.amberEarned`/`amberBreakdown.total` still carry the full earned receipt (queued share + windfalls) so the modal itemization sums exactly. `refreshStats()` reloads from storage. Reports phase 5 when post-revelation.

**`useVictoryFlow()`** — Victory animation: star pop-in, modal reveal, phase flash, driven by a `VictoryStage` state machine (`idle → recording → choreographing → settled`) plus `victorySpinnerVisible` so no spinner flashes during choreography. `playVictorySequence(stars)`, `skipToEnd(stars)`, `resetVictory()`. `isProcessingVictory` lock prevents double-tap.

**`useVictoryOrchestration()`** — Post-victory cascade: glitch text, narrative micro-beats, animal whispers, interjections, home nudges. Generation-guarded async callbacks. Whispers are **frequency-gated** (exported `getWhisperChance(phase)`: 0.45 phases 0-3, 0.6 phase 4, always at phase 5 — the personalized whispers are the endgame feature); the roll happens BEFORE generation, so a skipped win also skips the gallery `recordWhisper` (a line the player never saw must not fill the archive). The interjection overlay renders with `pointerEvents="none"` so it never blocks board input.

**`useDialogueFlow()`** — Animal dialogue sessions, cooldowns, trigger word reactions, sacrifice reactions, cross-animal references, coordinated events, narrative seed/callback + Phase-2 exhaustion-pool delivery, Phase 5 post-revelation routing (with a `hasMore` override so Phase-5 sessions never dead-end).

**`useUnlockFlow()`** — Home unlock flow: in-world room/animal prompts, purchases, intro dialogue for new characters.

**`useOnboardingFlow()`** — Cold-open onboarding state machine: self-directed opener board → invite Fox on home → pit → home (legacy guided-puzzle steps kept for resume compatibility). Fox text/step helpers, two-step skip, pit offer-complete.

**`useDreadEffects()`** — Crimson pulse overlay + screen shake for dread words (Phase 2+, phase-scaled intensity).

**`useSpeedTimer()`** — Speed variant countdown with `onTimeUp` callback.

**`useAchievementQueue()`** — Achievement checking + toast queue processing.

**`useAutosave()`** — Debounced mid-session puzzle state autosave.

**`useScreenInsets()`** — Safe-area insets via `react-native-safe-area-context` (`SafeAreaProvider` wraps the app root); used by all screens in place of the old hardcoded status-bar padding.

### App Bootstrap & Reliability

- `installGlobalErrorHandler()` (errorReporting.ts) is called at App.tsx module load — global JS errors and unhandled promise rejections are captured into the event log. `ErrorBoundary.componentDidCatch` also forwards React render errors through `reportError()` (source `react_error_boundary`), so both async and render-time failures land in the same pipeline. **Render coverage:** `home` and `puzzle` carry their own inner boundaries; an outer catch-all boundary wraps `renderScreen()` so a render error on the secondary screens (settings/stats/ledger/gallery/pit) returns the player home instead of crashing the whole app. Crash capture is local-only (500-entry buffer).
- Frame-rate monitoring (`performanceMonitor.startFrameMonitoring`) is diagnostic-only — its samples are never read in production — so it is gated behind `__DEV__` (and stopped on unmount) and never runs a perpetual `requestAnimationFrame` loop on a player's device.
- The default export `App` is a bootstrap gate: it installs the cloud provider + auto-restores a fresh install — the restore is **raced against `BOOT_RESTORE_RACE_MS` (2.5s)** so a slow network can't stall first launch; a restore that lands late re-runs migrations and **remounts `MainApp` via an `appEpoch` key** so the restored save takes effect without a manual restart — then awaits `runMigrations()` (dataMigration.ts), `initCosmetics()`, `initHints()`, `loadEntitlements()` and `loadPixelFonts()` **before** mounting `MainApp`, so service caches (including the Patron/ad-free/first-purchase sync cache) always read correct values on first render, then **reconciles the pending-IAP-grant ledger** (`reconcilePendingConsumableGrants` → apply reward → `acknowledgeConsumableGrant`; at-least-once, so a kill between store success and grant can never lose a paid purchase). `initIAP()`/`initAds()` are **fire-and-forget** — the first frame never waits on billing config or the ads consent → SDK init → preload chain. Renders a **branded boot screen** (the wooden wordmark + a quiet spinner) while booting; failures log and never block launch. Notification scheduling is NOT done blind at mount: `scheduleAllNotifications(persistence.currentPhase)` runs once persistence hydrates, so the reminder ladder is always written with the real phase's copy (the old mount-time `scheduleAllNotifications(0)` rewrote it bright).
- Every scheduled notification carries `data.target` (`'daily' | 'home'`); App's `addNotificationResponseReceivedListener` routes taps accordingly, and a **cold-start tap** (notification launched the app — never delivered to the runtime listener) is routed once via `getLastNotificationResponseAsync`, deferred ~1.2s so persistence state hydrates first. Deep links use the same pattern: the Linking subscription mounts once (handler in a ref) and the launch URL is processed exactly once with the same deferral. An AppState listener re-runs the daily launch effects (login reward, streak-freeze check, notification reschedule, stats refresh) when the app foregrounds on a **new local day**.
- Android hardware back: sub-screens navigate home (puzzle screen also resets transient UI state); home lets the OS exit; back is swallowed during onboarding.

### Screen Navigation

State-based routing in `App.tsx`. Screen transitions use an opaque overlay pattern: overlay fades IN (120ms), screen swaps while hidden, overlay fades OUT (180ms) after a **double `requestAnimationFrame`** (a single frame callback can fire before React commits the batched swap, so the cover began lifting over the outgoing screen — the transition flicker). Overlay/root `backgroundColor` dynamically matches destination via `getScreenBackgroundColor()`. Instant when `reducedMotion` enabled.

### Victory Flow

1. `isProcessingVictory` lock prevents double-tap; the mid-puzzle autosave is cleared at completion AND at every victory-exit (`startVictoryExitFlow`) so Play can never resume a finished puzzle
2. Record stars, award amber (per-puzzle amber deferred to harvest; one-time windfalls credit the balance instantly — see Offering Pit Economy), check achievements
3. Choreographed sequence: stars pop in with 200ms stagger → modal scales in; the entrance choreography is **tap-to-skip** (tap anywhere → `skipToEnd`)
4. VictoryModal shows: ritual echo chain, named incantation (Phase 2+), words offered count, amber breakdown (itemized — the REAL itemization threaded from `awardPuzzleAmber` as `amberBreakdown` on VictoryData via useGamePersistence, not a local recompute), action buttons
5. Phase transitions are **deferred** — `pendingPhaseTransition` set, VictoryModal shows pit hint, player must visit pit for ward ignition ceremony
6. Post-victory effects: AnimalWhisper (1.2s delay, frequency-gated — see `useVictoryOrchestration`), interjection/home nudge (2.5s delay, 30% chance; the interjection overlay is pointer-transparent), ritual micro-event (Phase 2+, 60% trigger)

**Victory toast queue (v1.3.2):** the victory chain's transient messages (fresh-variant/streak/quest receipts, speed-record beats, hint-grant receipts, soft nudges...) no longer race each other through direct `setMessage` calls — they enqueue into a **sequential priority toast queue** in App.tsx (rank order receipt > info > nudge; each toast holds the slot `VICTORY_TOAST_DURATION_MS` (1900ms), first toast after a `VICTORY_TOAST_INITIAL_DELAY_MS` (600ms) settle). Priority applies to queued-but-unshown toasts only. The queue is cleared on every victory-exit path, on new-board starts, and on unmount, so a toast can never leak onto the next board.

**Swift Victories** (`settings.swiftVictories`, SettingsScreen toggle, default off): a **routine** win renders a compact instant result strip instead of the full choreography. `isRoutineVictory` in `useVictoryFlow.ts` gates it — the daily, the mandatory-harvest gate, phase transitions, first-completion/milestone/streak-milestone bonuses, quest turn-ins, high-ritual-energy wins (≥ `RITUAL_MICRO_EVENT_MIN_ENERGY`), and the first `SWIFT_VICTORY_MIN_PUZZLES` (20) puzzles ALWAYS get the full modal. The puzzle `Toast` is phase-aware (`phase` prop → `getToastTheme`, contrast-audited per phase group).

### Offering Pit Economy (Deferred Amber)

Puzzle completion queues the PER-PUZZLE amber in harvest batches instead of crediting directly. Player must offer batches in the Offering Pit to convert to spendable amber.

**Windfall split (pre-launch fix)**: only the per-puzzle amber defers — `useGamePersistence.recordVictory` enqueues exactly `amberResult.amount` (base + star/streak/challenge/patron/surprise/resonance, plus the variant/fresh-variant bonuses folded into `amount` before enqueue). The one-time WINDFALLS — puzzle-count milestone, first-completion, and streak-milestone bonuses — credit the spendable balance IMMEDIATELY inside `awardPuzzleAmber`, regardless of `creditToBalance` (a "+150 Century milestone!" is a moment, not a harvest, and must be spendable without a pit detour). `VictoryData.amberEarned` / `AmberBreakdown.total` remain the FULL earned receipt (queued share + instant windfalls), so the VictoryModal itemization still sums exactly; `totalAmberEarned` counts every part exactly once either way; windfalls stay amber-only (never phase progress). The auto-collect window credits batch + windfalls to the same total as before (no double credit, no loss); routine wins on the compact swift strip can never carry a windfall (`isRoutineVictory` excludes milestone/first-completion/streak-milestone wins), so its "gathered for the pit" label stays honest. Pinned by regressions in `amberCurrency.test.ts` + `useGamePersistence.test.ts`.

**Flow**: Puzzle complete → `enqueueHarvestBatch()` (per-puzzle amber only) → VictoryModal shows "Collect Now" → pit screen → tap floating words to devour → `offerBatch()` credits amber.

**Crash-safe crediting**: `offerBatch`/`offerAllBatches` don't just delete the batch — the released amber moves into a `pendingCredits` ledger **inside the same persisted write**, and the pit credits via `awardBonusAmber` then acks (`acknowledgeBatchCredit`); a kill between offer and credit is recovered by `reconcilePendingCredits()` on pit load (orphaned credits re-apply, the ledger entry is the dedupe). The player's **first real manual offer** logs a `first_manual_harvest` funnel event (and sets the mandatory-harvest learned flag, below).

**Auto-collect window**: through the first `AUTO_COLLECT_PUZZLE_LIMIT` (8, `gameBalance.ts`) puzzles, amber auto-credits without a pit visit (the auto-collect path sets `VictoryData.autoCollected`). The VictoryModal shows an in-world reason via `getAutoCollectCaption(phase)` ("The house carries your words down to the pit for you, for now.") — lore, never a "tutorial" voice — so the automatic reward reads as the house doing the ritual labor for a newcomer.

**Mandatory first-harvest gate (repeat-until-learned)**: every victory past the window with a real batch waiting (`completedTotal >= AUTO_COLLECT_PUZZLE_LIMIT + 1`, outside onboarding, no phase-transition ceremony already claiming the pit, `!hasSeenMandatoryHarvest()`) sets `VictoryData.mandatoryHarvest` in the App victory chain. The VictoryModal then **forces** the pit before the player can continue: it hides Next Level / Home / Share (same `mustVisitPit` gate the phase-transition ceremony uses) and shows `getMandatoryHarvestText(phase)` + `getMandatoryHarvestCTA(phase)` as the only action — teach the pit by using it, with a lore beat instead of a passive Fox card. **The `wordshift_mandatory_harvest_seen` flag means LEARNED, not shown**: it is set only when the player completes a real manual offer at the pit (`markMandatoryHarvestSeen` in OfferingPitScreen's `tryFinalizeBatch`/`handleHarvestAll`, skipped during onboarding) — never at gate-decision time — so the gate re-fires on every eligible victory (standard, daily, variant) until a genuine harvest happens, and no interruption can silently consume the teaching beat. Escape hatches are closed in App.tsx: hardware back over a pit-mandatory victory routes to the pit (same as the CTA), deep links and notification taps are swallowed while the gate modal is up, and `maybeShowVictoryInterstitial` exempts `mandatoryHarvest` exits. A **Fox pit-arrival intro** completes the beat in-world: while the harvest is unlearned, arriving at the pit with batches waiting (outside onboarding, no phase ceremony claiming the pit) pops a FoxGuide dialogue teaching the tap-to-offer (`shouldShowHarvestPitIntro` pure decision in OfferingPitScreen + `getMandatoryHarvestPitIntroLines` in phaseNarrative) — the victory gate says the house stopped carrying, Fox at the pit says what to do about it. Repeat-until-learned like the gate: dismissing the card does NOT set the learned flag, only a real offer does, and the words stay tappable behind the card. A **one-time home safety net** (`harvest_gate_intro` in HomeScreen, own flag `wordshift_harvest_home_intro_seen`, copy `getHarvestHomeIntroLines`) has Fox explain the pit from home if the player still lands there unlearned with batches waiting; dismissing it does NOT set the learned flag. A **gentle heavy-pit nudge** (`harvest_heavy_nudge`, once per app session, no persistence) fires when `pendingAmber >= HARVEST_NUDGE_MIN_AMBER` (150, gameBalance) after the pit is learned (copy `getHarvestNudgeLine`). The learned flag stays deliberately **decoupled** from the legacy `wordshift_pit_harvest_intro_seen` (the old passive puzzle-8 Fox card set that legacy flag on existing saves; reusing it would have suppressed the gate for returning players — pinned by `mandatoryHarvestGate.test.ts`). All three keys are cloud-synced + cleared by Reset All.

**Pit Features**: Flying mini candy-tile words, tap-to-devour spiral animation, multi-layered pit glow (4 concentric ovals), ward marks (7 circles showing phase progress), ward ignition ceremony for phase transitions, phase-aware background images.

### Phase Transition System

Phase transitions are deferred, not instant. When `phaseProgress` crosses a threshold, `pendingPhaseTransition` is set. Player visits pit → ward marks illuminate → tap to confirm → ignition ceremony → `PhaseTransitionOverlay` cinematic → phase advances.

Ward marks: 7 circles hugging the pit opening's own ellipse (same radii + a small uniform offset, `PIT_WARD_RIM_OFFSET` — never a differently-proportioned arc), set into a **ward ring** drawn on that same radius (circle + `scaleX`, no SVG; a soft halo ring behind it is the Android-safe glow technique, never `shadowRadius`) whose brightness scales with `phaseProgressFraction`. The ring and the marks share one `wardsVisible` gate (`phase < 4`): the marks used to additionally require some progress, so a player at exactly zero progress saw no track at all, and each mark now sits on a dark seat so an unlit station reads as a station rather than a gap. Phase-aware colors (turquoise → purple → crimson). Pulsing when transition ready. **Continuous progress in every phase**: the next unlit ward "charges" with partial-opacity lit color proportional to sub-dot progress (`wardChargeFraction`), and the cryptic hint line appears from 15% progress — the later phases are 3-5x longer than the first, and whole-dot steps alone read as stalled.

**Reserve-ahead (pay now, build at the gate):** the gates are tuned for a baseline earner, so a fast/skilled player (HARD + achievements + quests) reaches a gated room's amber cost well before its level gate and would otherwise sit on idle amber behind a wall. **Skip the wait (pay a premium, unlock NOW):** alongside Reserve, a gated room the player can afford at a **premium** offers a **Skip the wait** shortcut — unlock it immediately, bypassing the level gate. `getUnlockSkipCost` = `ceil(cost × (1 + UNLOCK_SKIP_PREMIUM))` (premium = 0.5 in `gameBalance.ts` as of v1.3.2 — skip = 1.5× build cost, so the gated builds at 200-550 amber skip for 300-825); `canSkipUnlockGate` mirrors `canReserveUnlock` but requires the premium be affordable and no reservation pending (skip and reserve are mutually exclusive); `skipUnlockGate` spends the premium via `unlockRoom`/`unlockAnimal` and unlocks right away (celebration + character intro like a normal purchase). ### Dialogue System

**1,742 base dialogues** (134 per animal across 13 animals; every line scored against a McKee-based dialogue rubric) + **260 post-revelation** (20 per animal) + **130 Phase-2 exhaustion-pool lines** (`PHASE2_EXTRA_DIALOGUES`, 10 per animal):
- Phase 0: 24, Phase 1: 28, Phase 2: 22 (incl. question-web hook), Phases 3-4: 30 each, Phase 5: 20 each. Each phase block is written as session-sized mini-chapters (3 lines/visit at Phases 0-1, 5 at Phases 2-3, 6 at Phase 4) with end-of-session hooks and continuing story threads. **Doubling shifted every phase-start index — dataMigration v4 (`remapDialogueIndexV4`) remaps saved `lastDialogueRead` values to the same (phase, offset) position; never resize a phase block without a companion migration.**
- Counts are enforced by `configValidation.ts` (`EXPECTED_DIALOGUE_COUNTS_BY_PHASE`, `EXPECTED_PHASE2_EXTRA_PER_ANIMAL`=10) — update it when adding lines

**Session mechanics**: Max dialogues per session phase-aware (3-6). Cooldown: 2-5 puzzles between sessions. Grace period for newly unlocked animals. **Badge honesty (finite phases):** the stored dialogue index used to cap at the last line (`total-1`), so a fully-read animal's `!` badge would re-light after every cooldown while the session showed only "Close" — reading as *stuck* (lagging animals like the sloth hit this first, since their block is small relative to the global phase). `closeDialogue` now performs a **terminal read**: closing while on the last available line advances the stored index PAST it (to `total`) so the badge goes honest-dark until genuinely new lines exist (phase advance / newly unlocked animal). The cycling pools (Phase 2 exhaustion, Phase 5 post-revelation) are excluded (they always have more). `getAnimalsWithStatus` also resolves the stored index past locked-animal-gated lines, matching `useDialogueFlow.recomputeHasNewDialogue`. **Stale-closure guard:** `closeDialogue`'s badge-refresh write derives the committed index from CURRENT state inside the functional `setAnimals` update, never from the callback's closure — the forced close that ends a session runs in the same tick as `handleNextDialogue`'s index advance, and writing the closure's one-line-behind copy back used to re-serve the last-read line at the next grace-period session (newly unlocked animals skip the cooldown reload, so the rollback was visible only there). **Round-chaining ("visit next friend"):** when a session reaches its natural end (the button reads "Close") and another unlocked animal has news available RIGHT NOW, the dialogue card offers a second bevel labeled via `getNextFriendPrompt(phase, name)` (phaseNarrative) — tapping it runs the byte-identical close bookkeeping (`closeDialogue(false)`: terminal-read advancement, badge-honesty refresh) then opens the next animal through the normal `handleAnimalTap` path, ending the 13-stop errand of backing out to home between every visit. The candidate is resolved by the pure, order-stable `findNextAnimalWithNews` (exported from `useDialogueFlow`; wraps in unlock order, never returns the current animal) filtered through `isChainCandidate` — the synchronous badge-equivalent availability signal (unlocked + `recomputeHasNewDialogue` + not on cooldown + in-session budget remaining), so the button never leads to a cooldown dead-end; `handleAnimalTap` still re-checks availability itself, so a state change between render and tap degrades to the standard cooldown message. Never offered during onboarding or while an intro override / character intro owns the dialogue surface; the resolution is fully synchronous (HomeScreen computes it at the session-end render only).

**Rich interaction layers**:
- **Cross-animal references**: Phase-scaled frequency (20% → 60%). Vanguard animals get guaranteed first ref at each new phase. ## Incantation System (Puzzle-Narrative Connection)

The core system making puzzles feel like rituals:

- **Ritual Word Memory**: Every word formed is recorded (capped at 500). `recordRitualWords()` in `amberCurrency.ts`.
- **Ritual Echo**: VictoryModal shows completed word chain. Styling evolves: bright candy → muted → dark/vertical arrows. Header: "Your Word Journey:" → "The Offering:".
- **Named Incantations** (Phase 2+): Deterministic chain names. Phase 2: "The HEAT Dance". Phase 4: "Offering: VOID to DOOM".
- **Ritual Energy**: Dread word presence scored 0-10. Each point adds 0.1 to `phaseProgress`. High-energy puzzles (7+) trigger micro-events.
- **Word Ledger**: Scrollable screen of all formed words. Dread words highlighted at Phase 2+.
- **Animal Whispers**: 364 lines (5 per animal per phase, except Phase 4 which has 3 each; 13 animals × 6 phases). Prefers animals matching puzzle trigger words. Frequency-gated per win since v1.3.2 (~45% phases 0-3, ~60% phase 4, always phase 5 — see `useVictoryOrchestration`).
- **Dread Word Visual Feedback** (Phase 2+): Crimson pulse overlay on dread word formation. Phase-scaled opacity (0.10 → 0.25).
- **Arrangement Pattern** (Phase 2+): Visual sigil lines connecting rooms on house exterior.
- **Room Word Echoes** (Phase 2+): Faint puzzle words scattered across room backgrounds.
- **Phase-Appropriate Windows** (Phase 1+): the room interiors are painted with bright day-sky windows that read as noon under a dusk/night sky. `processRawWorldArt.mjs` extracts a per-room window-sky mask (`assets/rooms/windows/<room>.png`, white on transparent — largest blue blob + mullion-split panes merged, clouds within the region included, monitors/globes/plants excluded) for the rooms with a clear sky window (`cozy_den/kitchen/study/office/garden`); the aquarium's water, the desert's already-night sky, and windowless rooms are deliberately untreated (verified against a per-room detection montage). RoomView overlays the mask with a `tintColor`+opacity from `WINDOW_TINT` so just the window sky recolors to the phase (day-blue → dusk rose → night dark) while the mullions/curtains and the warm lit interior (fireplace, lamp) stay. Since the house is a cutaway, windows show the view OUT — they darken at night, they don't glow.

### Move Resonance (evaluative depth)

The puzzle-side complement to the ritual systems: the game notices when the player **chose the deep word on purpose**. On each committed formed-word move, `usePuzzleGame` runs `collectDistinctOutcomeWords` from the PRE-move step state (the `hasAnyValidMove` enumeration, but collecting the distinct valid outcome words instead of short-circuiting — ~20-40 sync dictionary lookups once per commit; double-shift passes the MID-step state so the enumeration mirrors the completed step's real remaining decision space; Unbroken Weave filters spent letters). `isResonantChoice(chosenWord, outcomes)` (both pure/exported) then marks a **resonant choice** when (a) a real choice existed (2+ distinct valid outcome words), (b) the chosen word carries dread weight (`getWordPhaseTier >= 1`), and (c) no available alternative ran deeper (chosen tier ≥ max tier among outcomes). Consequences:
- **Amber**: `RESONANT_MOVE_AMBER` (2) per resonant choice, capped at `RESONANT_BOARD_CAP_AMBER` (6) per board (`resonanceAmberForCount`) — a garnish, not a farm. Threaded from the completing move (`resonantChoiceCount`/`resonanceAmber` on the move result) through `useGamePersistence.recordVictory` into `awardPuzzleAmber({resonanceBonus})` (defensively clamped to the cap), additive to the REWARD only — like the Patron/surprise bonuses it **NEVER feeds phase progression**, so weighing options pays amber, never a faster descent. Itemized in the VictoryModal breakdown under `getResonanceBonusLabel(phase)` ("Deep words" → "Resonant words" → "Words it wanted").
- **Acknowledgment**: a resonant commit REPLACES the normal move message with `getResonantMoveMessage(phase)` for that commit only (never stacked with the pool draw; combo/streak bookkeeping still runs identically).
- **Records**: the board tally accumulates into a lifetime mastery stat (`recordResonantChoices`/`getResonantChoices` in `masteryRecords.ts`, migration-safe) and, on daily wins, an optional spoiler-safe `resonantChoiceCount` on the day's `dailyLadder` entry (stored only when positive — a count, never the words).
- **Bookkeeping**: per-move resonant flags align with `moveOutcomes`, so an **undo pops the flag and decrements the tally**; like moveOutcomes, resonance is NOT persisted — a restored autosave board restarts at zero. **Excluded entirely**: Blind Offering (the chain is judged once at the end — mid-board evaluation would leak validity) and the finale board (never pays it).

### Cottage Pixel Skin (`scripts/tools/generateUiPanels.mjs` → `assets/ui/panels/` + `theme/pixelSkin.generated.ts`)
The menus/modals/secondary screens are drawn in **generated pixel-art cottage chrome**, not flat styled Views: 9-slice wood frames with recessed parchment fills, 3-slice pixel-bevel buttons (true `up`/`down` pressed sprites), and wooden nameplate plaques. Key facts:
- **Generator**: `node scripts/tools/generateUiPanels.mjs` (pure Node, dependency-free PNG writer) draws full frame masters on an art-pixel grid (1 art-px = 3dp, baked at 9 real px/art-px for crisp @3x) and slices the 9-slice pieces from them, so seams match by construction. Edge strips are uniform along their stretch axis (all decor — nail heads, grain dashes, stepped radius-4 corners — lives in the fixed corner tiles): stretch-safe on Fabric. Warm near-black outlines (never #000), top-lit wood band, side-dependent recess transition. Re-run after palette changes; it also regenerates `src/theme/pixelSkin.generated.ts` (typed registry with static requires + dp constants).
- **Five materials, one geometry**: bright (phases 0-1) / dusk (2) / storm (3) / dark (4, ash paper + crimson accent, ink polarity flips to cream) / serene (5, mauve). The furniture *ages* with the descent — palette swaps over identical pixels. `getPixelSkin(phase, hostDark)` maps phases to skins (hostDark handles the dialogue-theme darkening at phase 2, one phase before the surface theme).
- **Painted accent inlay (v2 texture pass)**: every skin carries a second hue (`skin.accent`/`accentLo` — bright sage → dusk wine → storm slate → dark ember → serene mauve) baked as a carved inlay ring in panel frames, corner stitches on cards, and a carve line on plaques; panels also gained a 2-ring graded parchment vignette and corner wood knots, cards 1 vignette ring. The vignette rings are text-safe parchment tones — content only has to clear the WOOD band (24dp panel / 12dp card), not the full strip.
- **Runtime**: `components/ui/NineSlice.tsx` (`NineSliceFrame` — absolute corners with explicit px dims, inset-positioned wrapper Views with `width/height:'100%'` stretch Images for edges, SOLID parchment center View for guaranteed text contrast + low Image count in lists; `openBottom` for bottom sheets; honors every Fabric constraint from HouseWorld: no `resizeMode="repeat"`, no inset-only Image sizing) and `ThreeSliceStrip` (buttons/plaques). `PixelPlaque` = wooden ALL-CAPS nameplate (42dp, hard 3dp text shadow).
- **NEVER** apply `borderRadius`/RN borders over the PNG frames (CSS-rounding baked pixel corners is the #1 cozy-pixel anti-pattern). Frame strip thicknesses are `PANEL_EDGE_DP` = 30 and `CARD_EDGE_DP` = 18 (v2); required content clearance is the wood band (24dp panel / 12dp card — prefer ≥16dp on cards for breathing room). `CARD_CORNER_DP` = 21, so a card-framed container must be ≥42dp tall/wide.
- Skinned surfaces: PanelCard + CandyButton internally (everything using them inherits), HomeScreen's HubRow/BevelRowButton + all its modal containers (sheets use `openBottom`), StoreModal/PatronModal cards, AchievementToast, Settings/Stats section plaques, and (v2 sweep) the HomeScreen animal-dialogue **bubble + Next/Close bevel** across all three dialogue instances (the main animal card, the intro-override popups incl. journal intro, and the journal spotlight — the bubble is a card-frame parchment tray, the button the cottage bevel via `BevelRowButton`; text ink is `panelSt.body` so it always matches the fill polarity), the Next Unlock signage bar + ambient home line (wooden card frames over the outdoor world, `getSurfaceTheme` inks + amber trough fill), ShopScreen rows, and the Offering Pit chrome (summary bar, Offer All `ThreeSliceStrip` bevel, empty state, ward-hint sign), and — last of the bespoke flat cards — the **VictoryModal** (9-slice panel frame + `CandyButton` bevels for NEXT LEVEL / CONTINUE / Share / Home). The victory panel is the one skinned surface that does NOT take the skin's parchment fill: `NineSliceFrame` is given `phaseTheme.modalBgColor` so every contrast pair inside the result screen keeps the value it was audited against and the frame is purely additive; `hostDark` runs off `phase >= 3` there (the modal's own fill flips dark one phase before the world's surface theme). Button ink colors ship in the registry (`skin.ink`), contrast-audited ≥4.5:1 per skin.
- **Text directly on `screenBg`** (screen titles, back chips, section labels between cards) must use `getSurfaceTheme(phase).headerTitle`/`headerMuted`/`headerChipBorder` — cream inks audited ≥4.5:1 on every group's dark screenBg. The card inks (`title`/`body`/`muted`/`primaryText`) are DARK on the light skins and vanish on screenBg (the "Tile Shop dark-on-dark header" defect).
- **Typography** (`theme/fonts.ts`): a **two-typeface system by ROLE** — **Figtree** (SIL OFL, static Regular+Bold instanced from the Google variable font) for the **HEADER / title / plaque / button / prominent-bold chrome** (the `PIXEL_FONT`/`PIXEL_FONT_BOLD` role, 245+ call sites), and **Shantell Sans** (SIL OFL, the cozy handwritten face) for **BODY / running text / dialogue / inline emphasis AND the letter tiles** (the `BODY_FONT`/`BODY_FONT_BOLD`/`BODY_FONT_ITALIC` role). Keeping body-bold and the tiles on Shantell avoids a font switch mid-sentence and preserves the signature tile look. Every face's family name carries its weight/slant (`Figtree-Bold`, `ShantellSans-Italic`, …), so a `fontWeight`/`fontStyle` on top always resolves to a real face and iOS never falls back to the system font (the trap the single-weight Kurale hit). The role constants (`PIXEL_FONT*`/`BODY_FONT*`) are the single switch point — repoint them to move a role to a different face. `installGlobalFont()` still forces Shantell-Regular as the base on every unstyled `<Text>` (so "the rest" defaults to Shantell; explicit role styles win). Registration is **platform-split**: ANDROID embeds every face natively via the `expo-font` config plugin (`app.json` → plugins → expo-font → android.fonts builds a real multi-weight `<font-family>` XML per face — runtime `Font.loadAsync` on Android only registers the NORMAL style, so bold would silently fall back to the system font; hence NO loadAsync on Android); iOS loads at runtime via `loadPixelFonts()` (awaited in App's bootstrap `Promise.all`, warm before first render; failure falls back to the system font). Jest stubs `expo-font` via `moduleNameMapper` (`__mocks__/expoFont.ts`) and maps `.ttf` requires to a file mock.
- **Dialogue nameplate relocation**: the animal name sits as a centered **nameplate below the sprite portrait** (not a header row above the text) across every dialogue box — the main HomeScreen animal card, the intro-override popups, the journal spotlight, and both FoxGuide variants — reclaiming the wasted top strip so the speech bubble starts at the top of the text column. ## Onboarding (Cold-Open Intro)

**The shipped flow is a COLD OPEN, not a guided tour** (`OnboardingStep` in `services/onboarding.ts` + `useOnboardingFlow.ts`): a fresh install (`not_started`) resolves to `cold_open_puzzle` and lands DIRECTLY on curated EASY board 0 — no home screen first, no named guide. A warm, **unnamed** voice sets the one rule in a single line (`COLD_OPEN_INSTRUCTION` — it never points at the exact letter, the solve stays the player's own), reacts once with delight on the first committed move (`COLD_OPEN_FIRST_MOVE`, keyed on history length reaching 1 so it fires exactly once and never stomps invalid-drop feedback), and — added in the v1.3.2 pass — teaches the marks once on the FIRST letter pick-up before any commit (`COLD_OPEN_PREVIEW_TEACH`: green check / red cross previews + undo, ref-guarded to once, fired while the ghost previews are actually on screen — the tools are taught at the exact moment they first matter). Fox appears only AFTER the first win:
1. `cold_open_puzzle`: the self-directed opener board. The victory Continue routes to `home_empty` (board cleared).
2. `home_empty` → `fox_invited`: the empty home; tapping the den invites Fox, who acknowledges the already-solved puzzle — the player learns WHO was speaking, turning the opener into the quiet hook: something warm was already helping before it was ever invited in. Ember's faint wrong-note ("I have been hoping for someone like you for the longest time") closes the beat.
3. `going_to_pit` → `pit_intro` → `pit_offering`: Fox explains the pit in ONE card, then a standing FoxGuide prompt (`pit_offering_prompt`, no continue button until offered) tells the player to **tap each floating word** to offer it — the step only advances once every word is devoured (no auto-offer; a fallback only arms if the step is reached with nothing offerable). A **stalled-pending safety net** (`PIT_ONBOARDING_STALL_RESCUE_MS` = 30s, reset on every successful devour) auto-offers the remainder and completes the step so a confused player can never soft-lock onboarding.
4. `returning_home` → `unlock_explained` → `complete`: two Fox beats — the happy loop plus where the pit entrance lives (the in-world path is the only route back to the pit), then "come back each day".

During onboarding: simplified UI (no difficulty selector, stats, NEW button). Backward compatible with the legacy tutorial flag (old players who completed the original tutorial skip straight to `complete`). Persisted via `wordshift_onboarding_step`; `onboarding_step`/`onboarding_complete` funnel events fire from `setOnboardingStep`. **Legacy-step compatibility:** the old guided-puzzle steps (`going_to_puzzle`/`puzzle_tutorial`/`puzzle_complete`) remain VALID states with their Fox lines intact, so installs interrupted during the previous onboarding resume safely — the guided-board machinery (`tutorialGuidance` glow highlights, the compact FoxGuide card that dodges the active board zone via `tutorialFoxAnchor`, the ✓/✗ reinforcement beat) still serves that resume path. **Resume resilience:** transient steps only exist for a `setTimeout` window and have no owning screen on relaunch; `useOnboardingFlow.normalizeResumeStep` snaps them forward to a stable target, and `App.tsx`'s resume effect routes `cold_open_puzzle` through `resolveColdOpenLaunchRoute(hasPlayableAutosave, puzzlesSolved)` — a persisted win beats a stale PLAYING autosave (→ `home_empty`), else restore the exact autosaved opener board, else start curated board 0 fresh; the legacy `puzzle_tutorial` step re-inits a live guided board — so a kill mid-onboarding can never strand a new player on a dead screen. **Skip is two-step from every step**: on the cold-open board a Skip chip confirms via a game alert (`handleColdOpenSkipPress`, copy via `getSkipConfirm*` in phaseNarrative — "Keep going" prominent, "Skip it all" quiet); the FoxGuide steps confirm in-card. Only the confirmed skip runs the **clean exit**: it cancels pending step timers, persists `complete` (which atomically collapses every guidance surface), abandons the opener/guided board (`clearBoard` + `clearPuzzleState`), and lands on the full home screen. FoxGuide renders nothing when it has no text (no empty-card state), and its cards are the light lavender style at every anchor (no dark variant). A session that contained onboarding also defers the daily-login claim to the next launch (see Currency).

## Key Services Detail

### Puzzle Generation (`localGenerator.ts`)

Two-track generator with pre-computed indices:

- **Adjacency index**: `getInsertionIndex(wordLength)` — O(1) lookup for letter insertion candidates. Cached per word length.
- **Removal index**: `getRemovalIndex(wordLength)` — inverse mapping for reverse chain generation.
- **Standard**: Forward DFS, 2.5s timeout, 3 candidates, score ≥ 45. Anti-boring detection (penalizes S→plural, ED→past tense, etc.). **Forced-start (echo) boards** relax acceptance to `FORCED_START_MIN_SCORE` (20) — a `forcedStartWord` shrinks the candidate space so the normal 45 floor would starve echo-puzzle generation. **Multi-route final pick (v1.3.2)**: the exported pure helper `pickMultiRouteCandidate<T>` runs at the FINAL best-of-3 pick — the highest-scoring candidate with `completePathCount >= 2` (via `analyzeStandardBranching` with tight caps `{pathCap: 8, stateCap: 500}`) wins, and the best single-route ships when none qualifies. **Trap tie-break (Depth Levers Pass)**: an optional `hasTrap` predicate (`trapStepFraction > 0`) breaks EXACT score ties among qualifying multi-route candidates toward the trap-bearing one — score stays primary, and single-route candidates never gain from traps. Skipped entirely for `forcedStartWord` (echo) boards, `requireReverse` chains, and <2-candidate lists; the analysis runs after the search loop ends, so timeout/search behavior is untouched. The double-shift generator's identical-looking pick block deliberately does NOT get the preference (standard-only by design).
- **Reverse**: `generateReverseChain()` — random sampling + `isReverseSolvable()` validation. 25s timeout. `relaxBoring` flag widens pool.
- **Double shift**: `generateDoubleShiftPuzzle()` — 2-letter moves, `getDoubleInsertionIndex()` for pair lookups. Position-based locking via `receivedPositions`.
- **Phase-tiered dread words**: 615 words in 4 tiers. Scoring: `phase² × 2.5 × proximity_multiplier`.
- **Quality scoring**: Position preference (middle > edge), semantic journey bonus, word freshness, dread tier proximity.

### Amber Currency (`amberCurrency.ts`)

Core economy manager. Key functions:
- `awardPuzzleAmber()` — Returns balance/phase/streak + `phaseTransitionPending`. Deferred: sets `pendingPhaseTransition` instead of bumping phase. Crediting split (pre-launch fix): with `creditToBalance=false` (the recordVictory path) the per-puzzle `amount` stays deferred for the pit, but the one-time windfalls (milestone / first-completion / streak-milestone) credit `progress.amber` immediately either way — amber-only, never phase progress, `totalAmberEarned` counts each part exactly once. Takes `options.resonanceBonus` (clamped to `RESONANT_BOARD_CAP_AMBER`, returned itemized as `resonanceBonus` in the breakdown; additive to the reward only, never phase progression — see Move Resonance).
- `confirmPhaseTransition()` — Bumps phase from pending, clears fraction. Called from pit ceremony.
- `applyVariantAmberBonus()` — Variant bonus: the full configured multiplier always applies (the old anti-farm decay is REMOVED) plus a flat once-per-local-day-per-variant `FRESH_VARIANT_BONUS_AMBER` on top (`freshBonus`/`isFresh` returned so the VictoryModal can surface the moment). Amber only; never phase progress.
- `awardBonusAmber()` — General-purpose credit (streak milestones, etc.).
- `recordRitualWords()` — Record words, queue triggers, accumulate ritual energy.
- `consumeTriggerWords(animalType)` — Per-animal trigger word filtering.
- Phase tracking: `getFullProgress()`, `getPendingPhaseTransition()`, `getPhaseProgressFraction()`.
- Many one-time flags: `hasSeenChallengeIntro`, `hasSeenDailyChallengeIntro`, `hasSeenJournalIntro`, etc.

### Weekly Quests (`weeklyQuests.ts`)

Two rotating quest tiers (seeded deterministic, local-day bucketing): **5 daily** quests + **5 weekly** quests (`loadWeeklyQuests` returns a `CombinedQuestState`). Types: solve_count, solve_difficulty, earn_stars, daily_complete, no_hints, challenge_mode, earn_amber, visit_animals, streak_days, sacrifice_amber (Phase 4+ only), daily_streak, tend_amber (Phase 5+ only). Rewards: 30-140 amber base, phase-scaled (1.0x → 2.0x). The sink quests (`sacrifice_amber`/`tend_amber`) are strictly **net-negative at every phase** they can appear (reward < required spend even after phase scaling) — pinned by an economy guard test in `weeklyQuests.test.ts`. **Generation context is persisted with the quest state**: the last context-FULL load's context (puzzlesSolved, phase, unlocks…) rides inside the stored state, so a context-LESS load after a period rollover (e.g. the header pill refreshing at midnight) regenerates from the persisted truth instead of an optimistic default — no more impossible cross-midnight quests. Quests stay **dormant until `JOURNAL_UNLOCK_PUZZLES` (6)** (`QUEST_GENERATION_MIN_PUZZLES`, the same gameBalance constant HomeScreen's light-mode gate uses): a pre-journal load stores a dormant placeholder that activates in place, same period, once a context-full load reports the gate crossed. On **full-moon event days** one extra `event_`-prefixed daily quest slot appears (`EVENT_QUEST_TARGET` 3 solves, `EVENT_QUEST_REWARD_AMBER` 20; title via `getEventQuestTitle`).

### Live Events (`liveEvents.ts`)

Serverless live-ops: every "live" event is **pure deterministic math on the player's LOCAL calendar** (no event server, no Math.random, no network — same date, same answer, every device). The one shipped event is the **full moon** ("the night the sky thins"): full moons are approximated from the 2000-01-06T18:14Z lunar epoch + the mean synodic month; a local day is an event day when it overlaps ±1.0 day of a full moon → a 2-3 day window roughly monthly (`isEventDay`/`getActiveEvent`; DST-safe via consecutive local midnights). Surfaces, all bonus-only: a 🌕 badge on the DailyChallengeCard, a **+50% daily-challenge amber bonus** (`getEventDailyBonusAmber`, credited via `awardBonusAmber(..., 'event_daily_bonus')` — never phase progress), one extra `event_` daily quest slot (see Weekly Quests), and a once-per-session home ambient moon line (`getEventAmbientLine`, `eventAmbientShownRef` in HomeScreen). All copy is phase-aware via `getEventName/getEventBadgeLabel/getEventAmbientLine/getEventDailyBonusLine/getEventQuestTitle` in phaseNarrative.

### Whisper Gallery (`whisperGallery.ts`)
Collectible archive of all whispers, dialogue snippets, and narrative moments. Cap: 500 entries. Phase-aware titles. Entries are labeled with **poetic era names** (`getPhaseEraName` delegates to the canonical `PHASE_DESCRIPTIONS` titles in `types/homeWorld.ts`: Bright Days / Curious Thoughts / Deeper Questions / Growing Shadows / The Horizon / Terrible Peace) — never "Phase N" (narrative rule 7).

### The Offering / Sacrifice Mechanic (`sacrifice.ts`)
Phase 4+ **voluntary amber destruction** — the complicity beat. The amber is gone; the player gets **nothing mechanical** (never amber back, never phase progress — `updatePhase` is untouched). What it gives back is **recognition**, made richer in the "make it special" pass so the reward is pure flavor:
- **The altar stays OPEN** across repeated offerings (the modal no longer closes after each one — the #1 annoyance fix): the response renders inline ABOVE the still-tappable amount chips, the balance updates live, and a "Done" button ends the session.
- **In-session devotion streak**: consecutive offerings in one open session escalate the arrangement's response tone via `selectOfferingResponse({count, sessionStreak, phase, everything})` — calm → leaning → fervent (streak ≥3 / ≥6). Phase-aware pools: dread at Phase 4, serene at Phase 5. Milestones (2/3/5/10/25/50/100) still override and keep their contract keywords; the first offering keeps its "arrangement" welcome.
- **Devotion tiers** (`DEVOTION_TIERS`/`getDevotionTier`, cumulative-count standing, flavor only): Noticed(1) → Marked(3) → Known(8) → Kept(20) → Beloved of the Pattern(50) → One of the Arrangement(100). `performSacrifice` returns `tierUp` on the offering that crosses a threshold (metadata only — never replaces the response copy) so the altar can announce it.
- **The monument**: `getArrangementHoldsLine(total, phase)` + the current devotion title/regard render in the modal — watching the total climb IS the reward.
- **"Offer everything"**: a two-tap-confirm button gives the whole balance at once, with its own bespoke response pool (pays off the 100-milestone "You gave everything").
- **Felt feedback**: a candle flare (native-driven `sacrificePulse` scale + glow, reduced-motion aware) + `hapticMedium` on each offering.
- **Milestone offerings become Whisper Gallery collectibles** (`recordWhisper`, attributed to Ember, the flame-oracle).
- **One-time Phase-4 intro** (`getOfferingIntroLines` in phaseNarrative, `introContext: 'offering_intro'`): Ember, robed, formally invites the player into the rite (serene phase-5 variant). Gated by `hasSeenOfferingIntro`/`markOfferingIntroSeen` — the flag rides the already-synced `wordshift_sacrifices` state (so it follows the player across devices and clears on Reset All).

### Room Upgrades (`roomUpgrades.ts`)
Phase 2+: one cosmetic enhancement per room (tier 1, 75-150 amber). Phase-aware descriptions. **Tier-2 "deepenings"** (`ROOM_DEEPENINGS`, 175-300 amber) open at **Phase 2** — the same gate as the tier-1 decorations they build on — and require the room's tier-1 decoration first (`purchaseRoomDeepening` / `areDeepeningsAvailable` / `getDeepenedRooms`, stored in a separate `deepened` map under the same `wordshift_room_upgrades` key). Opening both tiers in one phase turns two unlock cliffs into one continuous sink (decorate, then deepen) across the **mid-game spend valley (~puzzle 45–95 under the compressed arc)**, where the house has largely finished unlocking and amber piles up; deepenings never disappear, so slower players still find them later. HomeScreen "The House Deepens" section. Dread-leaning copy (the rooms turn unsettling, not cozy). **Tier-3 "attunements"** (v1.3.0): 3 levels per room (Kindled/Humming/Attuned, 150/200/250 amber, phase 2+, tier-1 prerequisite, deepening NOT required; ~7,800 total) stored as an `attunements` map under the same key; `getRoomEmbellishmentIntensity(roomId)` (0..1) drives the in-world rendering (hearth glow, sigil marks, dust motes, nameplate pips in RoomView). Cleared in Reset All; covered by `roomUpgrades.test.ts`.

### Notifications (`notifications.ts`)
Local push: daily reminders (phase-aware morning messages, scheduled as a ladder of non-repeating dated one-shots `DAILY_REMINDER_LOOKAHEAD_DAYS` (7) ahead, skipping today once the player has played — so a daily player never gets a redundant "puzzle is ready" ping; while the Daily Challenge is still **locked**, the ladder still arms but with generic come-back copy routed **home** — never "your daily puzzle is ready" for content the player can't reach), streak-at-risk reminders (7pm the next missed day when streak ≥ 2, copy via `getStreakRiskMessage(phase, streak)`), an **escalating win-back ladder** for lapsed players (6pm one-shots at +1/+3/+7/+14/+30 days, `WIN_BACK_RUNG_OFFSETS` — 5 rungs; rung 1 shifts to the day after the streak-risk ping for streak holders; copy escalates via `getWinBackMessage(phase, rung)` in phaseNarrative, with special finished-story tail copy on +14/+30 for post-revelation players), and a **weekly-quest-expiry** reminder (Sunday **17:30**, deliberately staggered off the 18:00 win-back rungs so both can never land in the same minute, before the local-Monday quest reset; `getQuestExpiryMessage(phase)`, only when the player has weekly-quest progress in flight or unclaimed reward). Every notification carries `data.target` (`'daily' | 'home'`) so App can route the tap. Each app session reschedules everything with the CURRENT phase — `setNotificationPrefs(prefs, currentPhase)` takes the phase too, so a Settings toggle never re-arms the ladder with bright Phase-0 copy; the streak/win-back/quest pings only fire on genuinely missed/relevant days. Phase 5 has distinct serene tone.

**Permission flow**: `scheduleAllNotifications()` never prompts — it only schedules when permission is already granted. The OS dialog is triggered solely by `requestNotificationPermission()`, reached two ways: the one-time contextual prompt after the player's 3rd+ victory (App.tsx `maybePromptForNotifications` → a styled in-game `NotificationPromptModal`, phase-aware + reduced-motion aware, NOT a bare OS `Alert`; copy from `getNotificationPromptText()`), or the Daily Reminders toggle in Settings. The prompt result is logged as a `notification_permission_result` event.

### Cloud Save (`cloudSave.ts`)
Client-side sync layer with a pluggable `CloudProvider` interface. A live Supabase provider activates when `supabaseUrl`/`supabaseAnonKey` are set in `app.json` → `extra` (**now configured**); it also powers the daily leaderboard + aggregate social proof. Falls back to `NoOpProvider` (no network I/O) when unconfigured. `collectLocalSaveData()` / `restoreFromCloudData()`. `SYNC_KEYS` lists the **actual** AsyncStorage keys each service writes (e.g. `wordshift_home_progress`, not `wordshift_progress`; includes `wordshift_daily_login`, `wordshift_cosmetics`, `wordshift_narrative_delivery`, `wordshift_daily_ladder`) — keep it in sync when adding a persisted key; `SYNC_KEY_PREFIXES` (`['wordshift_played_']`) prefix-syncs dynamic key families with no extra bookkeeping. Device-specific keys (`wordshift_device_id`/`install_id`/`wordshift_ad_pacing`), the local analytics buffer (`wordshift_event_log`), store-authoritative entitlements (`wordshift_entitlements`), the pending-IAP-grant ledger (`wordshift_pending_iap_grants`), and the sync-status meta key are intentionally excluded.

**Conflict guard**: `uploadToCloud(force = false)` skips the write and records `conflictDetected` in the sync status when the cloud row is **newer than this device's save** (another device played since), so a stale device can never silently clobber real progress. `updateSyncStatus` advances the baseline (`lastSyncTimestamp`) **only on success** — a failed/offline upload must keep the old baseline, or an offline victory's background upload would inflate it past any newer server save and permanently blind the guard. Settings → **Backup & Restore** surfaces the conflict with an explicit choice — restore the newer cloud save (which calls `onCloudRestored` → App's `rebuildSessionFromStorage({restartOnboarding:false})` so the running session actually re-reads the restored state), or keep this device's (force-upload); **both actions only clear the banner when the operation actually succeeds**. A successful download/restore clears the flag. `performNewCycle` (SettingsScreen) force-uploads so the new cycle always becomes the cloud row. Boot uploads wait on the fresh-install restore via `holdUploadsUntil` so a slow first launch can't push near-empty state over the row the restore is downloading. Known follow-up: the newer-than comparison uses wall-clock timestamps from two devices, so gross clock skew can still misjudge; the robust fix (server-assigned monotonic version) is a documented backend follow-up.

**Mid-session restore cache hygiene**: every service with a module-level in-memory cache that is ALSO in `SYNC_KEYS` exports an `invalidate*Cache()`, and `invalidateRestoredServiceCaches()` (cloudSave) calls all of them, so a mid-session restore (the appEpoch late-restore remount, or Settings' "Use the newer save") can never leave a warm pre-restore cache whose next write silently overwrites the just-restored save. When you add a synced key backed by a cache, add its invalidator to that list.

**Backend security is RPC-only with RLS** (capability model: knowing a row's unguessable owner/install id *is* the capability). The anon key has zero direct table access — grants revoked, RLS deny-by-default; saves, leaderboard, and social proof all go through SECURITY DEFINER RPCs (`sbRpc` in `supabaseClient.ts`, which exposes **no** select helper). Single exception: the telemetry `events` table is INSERT-only for anon. `docs/supabase/security_setup.sql` must be run in the Supabase SQL editor to apply this.

## Coding Conventions

- TypeScript with explicit types for props and state
- React Native StyleSheet (not inline styles)
- Functional components with hooks
- Import colors from `CandyColors` in `theme/colors.ts`; use `getPhaseTheme(phase)` for phase-aware
- **All player-facing text through `phaseNarrative.ts`** — never hardcode strings
- **Animation cleanup**: Store animation return values, `.stop()` in useEffect cleanup
- **Native driver preferred**: `useNativeDriver: true`; use opacity overlays instead of JS-bridge backgroundColor. As of the ship-readiness pass there are **zero `useNativeDriver: false` animations** in src/components — glows are pre-styled overlay Views with native-driven opacity
- **Device tier gating**: `shouldSimplifyAnimations()` to skip decorative animations on low-end
- **React.memo** on expensive pure components (e.g., Row)
- **MoveDelta pattern**: Undo uses lightweight deltas, not deep clones
- **Schema versioning**: `dataMigration.ts` for storage format changes
- **Concurrent spend guard**: `spendInProgress` flag in amberCurrency
- AsyncStorage with in-memory cache pattern (load → cache → return cached)
- TS strict: module-level nullable caches need local variable assignment
- `reducedMotion`: All animations must check and skip/set-instantly
- **Narrative consistency**: Any new feature must respect current phase. Cheerful-only-at-Phase-0.
- **No over-engineering**: Only make directly requested changes. Don't add features, refactoring, or docstrings beyond what's asked.
- Accessibility: `accessibilityLabel` and `accessibilityRole` on interactive elements; never convey information by color alone (see the ✓/✗ slot-preview prefixes); dark-phase text colors must hold ≥4.5:1 contrast against their backgrounds
- **No em dashes (—/–) in player-facing text** — dialogue, UI strings, alerts, accessibility labels. Use `...` for dramatic pauses, commas for asides, or split sentences (`noEmDashes.test.ts` guards this at runtime over the real content pools)
- Store/legal: privacy policy, terms, and data-deletion pages are **live and publicly accessible** via GitHub Pages (served from `docs/`). All three URLs are wired into `src/constants/links.ts` and surfaced in Settings → About (Privacy Policy / Terms of Service / Data Deletion rows); store-listing metadata in `docs/STORE_LISTING.md` points at the same live URLs

## Testing Patterns

- Shared AsyncStorage mock: `createMockAsyncStorage()` from `helpers/mockAsyncStorage.ts`
- `beforeEach`: call both `AsyncStorage.clear()` AND service-specific clear functions
- Puzzle generator tests mock `amberCurrency.getCurrentPhase` + all `wordHistory` functions
- Hook tests use manual React mock with stateStore Map + index rewind
- `DialoguePhase` is `0|1|2|3|4|5` literal — mock return values need `as number` cast
- Component tests use `jest.mock('react-native', ...)` stubs (Node env, no renderer)
- Performance monitor tests mock `requestAnimationFrame`, `cancelAnimationFrame`, `performance.now`
- Date-sensitive tests must build dates from local components (`new Date(2026, 1, 9)`), never ISO strings (`new Date('2026-02-09')` parses as UTC midnight → previous local day in timezones behind UTC)
- **Day-bucketing must use `services/dateUtils.ts`** (`getLocalDateString`, `getLocalDateStringDaysAgo`, `parseLocalDate`, `daysAgoLocal`) — these derive the calendar day from LOCAL components. Never reintroduce `toISOString().split('T')[0]` for streaks, daily challenge, or "played today" logic (it buckets by UTC and corrupts streaks for sub-UTC timezones). `amberCurrency.ts`, `dailyChallenge.ts`, and `HomeScreen` streak-at-risk all route through this helper.
- Tests whose code path calls `logEvent` should `jest.mock('../services/eventLogger')` so the 5s debounced flush timer can't fire after teardown
- Phase-threshold tests must use `PHASE_THRESHOLDS` values from `constants/gameBalance.ts` ([0, 16, 44, 84, 124]) — don't hardcode stale balance numbers

### Regenerating puzzle banks
0. **STANDARD banks: use the gated toolkit, not the legacy generators.** The shipped standard banks are the gated full regeneration (every board multi-route — see Pre-Generated Puzzle Banks): `cd mobile && bash scripts/runGatedRegen.sh <EASY|MEDIUM|MEDIUM_PLUS|HARD>` (loops `scripts/generateGatedBank.test.ts`, checkpointed + plateau-aware), then `node scripts/swapGatedBanks.mjs` to swap the finished sidecar over the live file. Re-running the legacy standard generators or `generateBranchingTopUpA/B` would rebuild the pre-gated (partly single-route) shape and lose the guarantee. Steps 1-4 below still apply to the reverse/double banks (and to the purge/recalibration after ANY regeneration).
1. `npm run generate:puzzles` (long-running jest generators in `scripts/`). Each generator enforces the bank-wide word saturation cap (`BANK_WORD_CAP` env, see Pre-Generated Puzzle Banks) and **checkpoints per puzzle** to gitignored `src/data/.bank_*_progress.json` / `.reverseBank*_phase*.json` files, so crashed/killed runs resume where they left off. Run jest with `--forceExit` (generators hold open handles after completion) and `NODE_OPTIONS=--max-old-space-size=4096`. Hot-loop mocks in these scripts MUST be plain functions, never `jest.fn()` — jest.fn records every call's arguments and a multi-hour DFS run OOMs the heap. `scripts/jest.config.js` runs ts-jest transpile-only (`isolatedModules`) for the same reason.
2. **Always** run `node scripts/tools/purgeProfanity.mjs` afterwards — the generator does not filter offensive words; the purge script removes them from both dictionaries and drops affected bank puzzles. **This is not optional and it is not only about the visible chain**: for double-shift boards the purge also evaluates the *drop1 intermediate* states (the transient word after the first of two letters lands), which is where slurs actually surfaced. Both the purge tool's file discovery (`/Bank.*\.ts$/`) and `vocabularyHygiene.test.ts`'s `BANKS` table must list **every** bank family — both were prefix-scoped to `puzzleBank*` when the 15 `lexiconBank*` files shipped, so the rare-word banks were generated and never screened, and 16 boards carrying ethnic slurs / sexual-violence terms as drop1 intermediates reached the repo (caught and purged 2026-07-24). Add new bank families to BOTH or they ship unscreened.
3. The blocklist lives in `scripts/tools/purgeProfanity.mjs` (`BLOCKED_WORDS`)
4. Recalibrate `src/__tests__/bankDiversity.test.ts` (per-bank cap = measured max, floors ~15% under measured) — it will fail loudly if a regeneration regresses variety

## Narrative Acceleration

Engaged players reach the Phase 4 reveal at the 90-puzzle floor (~day 11-12 at 8/day, finale ~day 15); an unaccelerated casual arrives near the weighted threshold (~124 — usually a little earlier, since ritual energy tops up weighted progress; ~day 45 at 2/day, post-revelation ~day 60). The `MIN_PUZZLES_FOR_PHASE` floors bind once weighted progress clears the thresholds ({1: 12, 2: 28, 3: 62, 4: 90, 5: 120} in gameBalance.ts):
- Three-star rate: a LINEAR ramp (no cliff) — 1.0x at/below `THREE_STAR_RAMP_START` (0.40), rising to the 1.5x ceiling at `THREE_STAR_RAMP_END` (0.60), so exactly 1.25x at a 0.50 rate; a one-point rate change no longer swings the reveal by weeks
- Long streaks (7+ days): 1.25x
- Hard difficulty: 1.5x
- Challenge mode: 1.5x (Blind Offering: 2.0x — the cap)

## Known Constraints

- `app.json` → `android.blockedPermissions` strips `FOREGROUND_SERVICE` + `FOREGROUND_SERVICE_MEDIA_PLAYBACK` (expo-audio injects them; the game plays foreground SFX only, and shipping the typed FGS permission triggers Play's Android-14 foreground-service declaration for a capability the app doesn't have). Do NOT remove the block unless background audio actually ships
- **Bundled PNGs must be real, clean PNGs or the Android release build dies at `:app:mergeReleaseResources` with `AAPT: error: file failed to compile`.** Two guards: (1) `app.json` → `expo-build-properties` sets `android.enablePngCrunchInReleaseBuilds: false` so AAPT2 skips re-crunching the already-optimized art (the ~3.5MB skies + pit backgrounds otherwise stress the cruncher and cause non-deterministic collateral failures). (2) Art edited in phone/photo tools (Google Photos etc.) is exported as **JPEG bytes under a `.png` name** or with an embedded color profile (iCCP) — libpng inside AAPT2 rejects both. Run `node scripts/tools/sanitizePng.mjs <file.png>` (from `mobile/`) on any externally-edited image before committing: it decodes via jimp (PNG *or* JPEG) and re-encodes through pngjs to a minimal `IHDR/IDAT/IEND` RGBA PNG. JPEG also **drops the alpha channel** (flattens transparency to a solid color), so for art that needs transparency (the per-phase foundations), re-apply the original's alpha mask rather than shipping an opaque box
- Standard/reverse/double_shift/**speed** at ALL difficulties serve from pre-generated banks (lazy-loaded). **Speed reuses the STANDARD bank family** (`getBankForSelection` allows speed; `getBankKey` maps speed → `std_<diff>` / `lex_std_<diff>`) — a speed board is a standard board played against the clock, so it no longer generates on-device (the +1 extension stays gated to `variant === 'standard'`, so speed keeps its base size). **Zero-wait board serving:** after the speed routing + the `lex_rev_expert`→`reverse_expert` remap, EVERY (variant × difficulty × lexicon) combination resolves to a pre-generated bank (with recycling), so the 30s on-device reverse path and the speed on-device path are both effectively dead. The only remaining on-device generation is intentionally-dynamic content: **echo puzzles** (every 5th Phase-3+ standard board, seeded from the player's own ritual words — a fast personalized forward-DFS with an instant bank fallback), the one-time **finale board** (bespoke, `buildFinalBoard`, 3s timeout + `CURATED_FINAL_PUZZLE` fallback), and the **daily** (seeded/deterministic so every player gets the same board). All three are fast and fall back to instant content; they are personalized/bespoke by design, not combo gaps.
- On-device timeout: 2.5s standard, 25s reverse, 5s double-shift. Wrapper: 4s/30s
- Fallback pool: 15 pre-validated puzzles across 3 tiers
- Dictionary: common English only (no proper nouns), 3-7 letters
- Arc layout uses `overflow: visible`
- Dialogue sessions persist across restarts
- House view: `react-native-gesture-handler` (vertical pan only). The pan is **native-driven**: the gesture writes `translationY` straight into `panRaw` via `Animated.event({useNativeDriver: true})` over an offset captured at BEGAN, and the rubber band is SAMPLED into the render interpolation rather than computed per frame in JS. Do not reintroduce a JS `onGestureEvent` that calls `setValue` — a per-frame JS hop plus style commit over this scene's ~30 animated children is what made the house scroll lag. The only per-frame JS left is the value listener that keeps `liveTranslateYRef`/`currentPanYRef` fresh (needed to capture a mid-spring base synchronously at BEGAN)
- TouchableOpacity in home components from `react-native-gesture-handler`; HomeScreen modals use react-native's
- Daily challenge uses Math.random override (concurrency-guarded)
- Victory flow: `isProcessingVictory` lock
- AnimatedBackground: opacity overlay (native driver compatible)
- Device tier detection is heuristic (PixelRatio + screen size)
- **expo-doctor is 20/21** as of 2026-07-24: the one failure is upstream SDK-56 **patch drift** (10 expo packages sit 1-2 patches behind, e.g. `expo` 56.0.15 vs `~56.0.17`) — not a code regression; `package.json` has not been touched. Run `npx expo install --check` before the production cut. The bar was 21/21 at the ship-readiness pass: `expo-asset` is an explicit dependency, the splash config lives in the `expo-splash-screen` config plugin (the deprecated top-level `splash` block and stray `newArchEnabled` were removed from `app.json`). Keep it clean — run `npx expo-doctor` after native-config changes

## Monetization

**Cosmetic Shop (amber):** `components/shop/ShopScreen.tsx` (`currentScreen: 'shop'`, reached from the **home utility menu** ☰) buys & equips **tile themes** and **confetti palettes** with amber, in two sections. Tile themes live in `theme/colors.ts` `TILE_THEMES` (six amber-priced sets, 300-1,000: Ember-warm/Deep-tide/Bone-quiet — these double as the Phase-5 Tending motifs — plus `theme_verdant`/`theme_static`/`theme_sovereign` at 650/800/1000, + a Patron-entitlement gold set); the equipped one is pushed into `colors.ts` via `setEquippedTileTheme()` (registration pattern → no import cycle) and resolved synchronously inside `getTileColor()`, so it stays phase-aware (phase overlays/glow apply on top). Confetti palettes live in `CONFETTI_THEMES` (five amber-priced, 250-550, incl. `confetti_verdant`/`confetti_sovereign`); an equipped one overrides the phase-default confetti in `Confetti.tsx` (via `getEquippedSync('confetti')`), with the phase-aware default when none is equipped. The amber catalog totals ~5,600. Amber purchase routes through `spendAmber(cost, 'cosmetic_<id>')` → `recordAmberCosmeticPurchase` (auto-equips); a "Need more amber?" row opens the Store (`onOpenStore`).

**Services (providers WIRED — live when configured, NoOp fallback):** As of the launch-prep pass, real provider adapters are registered in `App.tsx` and keys live in `app.json` → `expo.extra`, so the app ships with live IAP + ads when those keys are present; the NoOp providers remain the automatic fallback in Expo Go / when a key or SDK is absent.
- `services/entitlements.ts` — source of truth for owned items / Patron status (`isPatron()`/`isPatronSync()`, `grantEntitlements`, `setEntitlements`, `clearEntitlements`). AsyncStorage-backed, native-free.
- `services/iap.ts` — `BillingProvider` seam; holds `PRODUCT_IDS`/`purchaseProduct`/`restorePurchases`/`entitlementsForProduct` as pure code. **`services/providers/revenueCatBilling.ts`** (`createRevenueCatBillingProvider`) is the live RevenueCat adapter, registered via `setBillingProvider()` before `initIAP()`. Reads `revenueCatIosKey`/`revenueCatAndroidKey` from `extra`; products map to the `patron`/`adfree` entitlements. **`getProducts`/`purchase` MUST pass the CORRECT product category per SKU** — one-time/consumable products need `NON_SUBSCRIPTION`, the `supporter` subscription needs `SUBSCRIPTION`; a mismatch makes RevenueCat's Android fetch return `[]` and the Store reads "not available" (the NON_SUBSCRIPTION half was THE original launch blocker on the Play internal build; the subscription half was a revenue-pass regression fixed the same way). The adapter splits a mixed batch by `isSubscriptionProduct()` (`iap.ts`, source of truth = `SUBSCRIPTION_PRODUCT_IDS`), fetches each group with its own category (read off the loaded SDK's `PRODUCT_CATEGORY.*` with string fallbacks), and normalizes an Android subscription's `:basePlanId`-suffixed identifier back to the bare id (`revenueCatSubscription.test.ts`). `initialize()` also **silently restores entitlements**: it registers a customer-info update listener FIRST, then fetches `getCustomerInfo()` — a reinstall/new device gets its Patron/Remove-Ads back without the player finding the Restore button.
- `services/ads.ts` — `AdProvider` seam + ad policy as pure/testable code (`interstitialFrequency`, `shouldShowInterstitial`, rewarded daily cap, Patron suppression). **`services/providers/googleAdMobAds.ts`** (`createAdMobAdProvider`) is the live AdMob adapter, registered via `setAdProvider()` before `initAds()`; reads `admobInterstitialId*`/`admobRewardedId*` from `extra`. **GDPR/UMP consent is resolved strictly BEFORE SDK init and any preload** (single-flight gate; `initialize()` resolves immediately while the consent → init → preload chain runs in the background, so cold start never blocks on a consent form). `ads.ts` exposes `privacyOptionsRequired()`/`showPrivacyOptions()` — Settings → ABOUT shows a "Privacy Options" row only when required. AdMob app id is in the `react-native-google-mobile-ads` config plugin in `app.json`. **Interstitials are wired:** `App.tsx` calls `maybeShowVictoryInterstitial()` on the normal victory exits — next-level, home, AND the pit route (`handleNextLevel`/`handleReturnHome`/`handleGoToPit`) — exempting onboarding, the early window (`puzzlesSolved <= INTERSTITIAL_MIN_PUZZLES` (16) — v1.3.2 first widened it past the auto-collect window at 8 so the first interstitial never lands on the first mandatory-harvest sessions, then the pre-launch spacing fix raised 12→16: at 12 the first ad hit the exit of win 13, the SAME board whose start carries the one-time preview-graduation toast (`PREVIEW_GRADING_FULL_LIMIT`=12); at 16 the first ad lands on the exit of win 17, clear of graduation (board 13) and the challenge intro (15). The resulting early one-time-beat timeline: daily unlock 8 / mandatory first harvest 9 / reverse variant 10 / preview graduation 13 / challenge intro 15 / first ad on the exit of win 17. Deliberately no longer equal to `EXIT_NUDGE_MIN_PUZZLES` (12) — `runVictoryExitNudges` already skips when an interstitial showed, so they never stack on one exit), mandatory-harvest exits, pending phase transitions, queued final/post-revelation cinematics, and Phase 5 — so ads never interrupt a ceremony (incl. ward ignition) or the serene endgame. **The daily is exempt only from Phase 3 on** (`ads.isDailyInterstitialAllowed(phase)` — at the bright phases 0-2 the daily's reliably habitual session carries the normal interstitial cadence; from Phase 3 it's protected like the rest of the dread arc). `VictoryData.puzzlesSolved` feeds the cadence.
- **Restore Purchases** lives in **Settings → PURCHASES** (`restorePurchases()` from `iap.ts`) in addition to the Patron modal, satisfying store-policy's accessible-restore requirement. `app.json` adds `NSUserTrackingUsageDescription` for iOS ATT. **iOS monetization keys are still empty** (`revenueCatIosKey`/`admobInterstitialIdIos`/`admobRewardedIdIos` in `extra`, no iOS AdMob app id) — iOS falls back to NoOp until those are filled; Android ships fully monetized.
- `services/cosmetics.ts` — owned/equipped cosmetic state (amber-bought local + entitlement-granted). `ownsCosmetic`, `recordAmberCosmeticPurchase`, `equipCosmetic`/`unequipCosmetic`, `getEquipped`/`getEquippedSync`, `initCosmetics` (App bootstrap).
- Both adapters load their native module via a guarded **literal** `require('react-native-purchases')` / `require('react-native-google-mobile-ads')` / `require('expo-tracking-transparency')` (in a try/catch), and degrade to NoOp when absent, so the app still runs in Expo Go and all logic is unit-tested (`__tests__/monetization.test.ts`, `__tests__/providerAdapters.test.ts`). Native modules required for a real build: `react-native-purchases`, `react-native-google-mobile-ads`, `expo-tracking-transparency`. **Do NOT change these to `eval('require')` / a dynamic module string** — Metro only bundles a module it can see via a static `require('literal')`, so a dynamic require ships an empty bundle for the SDK and every purchase/ad silently no-ops on a real device (getProducts → [] → the Store reads "not available") even though it works in Jest/Expo Go. This exact bug shipped once and manifested as "purchases not available" on a Play internal-testing build.

**Patron amber bonus:** `amberCurrency.awardPuzzleAmber()` adds `PATRON_AMBER_BONUS` (+2, returned as `patronBonus`) when the Patron entitlement is set — additive to the REWARD only, **never** phase progress. `wordshift_cosmetics` is in `cloudSave.SYNC_KEYS`; `wordshift_entitlements` (store-authoritative) and `wordshift_ad_pacing` (device-specific) are excluded; cosmetic/entitlement keys are cleared in Settings → Reset All.

**The Store (consumable packs + hint economy + starter pack + cosmetic bundle):** `components/monetization/StoreModal.tsx`, opened from the **home utility menu** (🛒 Store), the **home header amber pill**, and the cosmetic shop's "Need more amber?" row (`onOpenStore` props). Sells four things:
- **Amber packs** (consumable IAP — `AMBER_SMALL/MEDIUM/LARGE`, amounts in `gameBalance.AMBER_PACK_GRANTS`): credit the **REWARD** balance via `awardBonusAmber(amount, 'iap_<sku>')`. The FIRST amber pack a player ever buys grants `FIRST_PURCHASE_AMBER_MULTIPLIER` (2x) its amount — one-time, consumed on first success, tracked alongside entitlements. Like every amber source they **never** feed phase progress, so pacing is identical for paying and free players — amber buys convenience for the cosmetic shop + amber sinks, not the story.
- **Keeper's Welcome** starter pack (one-time bundle — `STARTER_PACK` = `com.wordshift.starter`, `purchaseStarterPack()` in iap.ts): `STARTER_PACK_GRANTS` = 400 amber + 5 hints. Gated by the `starter_pack` entitlement, so it can be bought exactly once (repurchase is refused before hitting the store).
- **Hint packs** (consumable IAP — `HINTS_SMALL/LARGE`, `gameBalance.HINT_PACK_GRANTS`). Hints are now a **consumable resource** (`services/hints.ts`, key `wordshift_hints`): a player is seeded `STARTING_FREE_HINTS` once, earns more from the opt-in `hint_recovery` rewarded ad (`REWARDED_HINT_GRANT`), buys packs, or (v1.3.2) receives a **milestone trickle**: `grantBonusHint(source)` grants +1 when a puzzle-count milestone bonus lands and the balance is under `BONUS_HINT_SOFT_CAP` (10) — App wires it to `victory.milestoneBonus > 0` with a `getHintGrantMessage(phase)` receipt toast. `usePuzzleGame.handleHint` checks `hasHintSync()` and spends one via `consumeHintSync()` only when help is actually delivered; an empty balance raises `outOfHintsSignal` → App offers a rewarded clip / the store (`handleOutOfHints`). Spending a hint **still costs stars** (star penalty unchanged), so hints are convenience, never progression. The HINT button shows the live count (`HINT · N`). `wordshift_hints` is in `cloudSave.SYNC_KEYS` (purchasable → must follow the player); cleared in Settings → Reset All.
- **The Keeper's Collection** (non-consumable cosmetic bundle — `COSMETIC_BUNDLE` → `ENTITLEMENTS.COSMETIC_BUNDLE`): grants the exclusive `theme_eclipse` tile set + `confetti_eclipse` (both `kind:'entitlement'` in `cosmetics.ts`, palettes in `colors.ts`). Disjoint from the amber catalog (cash never buys an amber-priced cosmetic).
- `services/iap.ts` adds `CONSUMABLE_PRODUCTS`/`consumableReward()`/`purchaseConsumable()` — the consumable path grants **no** entitlement (repeatable) and returns the reward for the caller to apply (StoreModal), mirroring the codebase's "caller orchestrates the grant" convention. `iap_purchase` events are logged.
- **Pending-grant ledger (purchase recovery):** consumable purchases AND the starter pack persist the final reward to a ledger (key `wordshift_pending_iap_grants`) **before** `purchaseConsumable`/`purchaseStarterPack` returns — apply-then-ack (`acknowledgeConsumableGrant(grantId)`) gives at-least-once delivery, so a kill between the store success and the grant replays rather than loses a paid purchase. Reconciled at App bootstrap (`reconcilePendingConsumableGrants`, credited as `iap_recovered_<sku>`). The key is deliberately **NOT in `SYNC_KEYS`** and **NOT cleared by Reset All** — it represents store money owed to this device, not game progress.
- **Fallback prices:** the Patron / Remove-Ads CTAs render `PATRON_FALLBACK_PRICE` ($8.99) / `REMOVE_ADS_FALLBACK_PRICE` ($5.99) when live billing hasn't supplied a `priceString` (Expo Go / failed fetch), so the buttons never read as broken blanks.

**Monetization soft prompts (`services/monetizationPrompts.ts`, key `wordshift_monet_prompts`):** two one-time, frequency-capped nudges, both suppressed for owners. A **Patron nudge** (`consumePatronNudge`, after `PATRON_NUDGE_MIN_PUZZLES`) fires on a victory exit (`maybeShowPatronNudge` in `handleNextLevel`/`handleReturnHome`) and opens `PatronModal`. A **Remove-Ads nudge** (`consumeRemoveAdsNudge`, after `REMOVE_ADS_NUDGE_AFTER_INTERSTITIALS` interstitials actually seen — counted via `recordInterstitialSeen` once an interstitial shows) offers a gentle Alert → `PatronModal`. Decisions are pure/exported (`shouldShowPatronNudge`/`shouldShowRemoveAdsNudge`); state is device-local UX pacing (excluded from cloud sync, like ad pacing) and cleared in Reset All. Covered by `__tests__/{hints,monetizationStore,monetizationPrompts}.test.ts`. A parallel **share soft-prompt** (`services/sharePrompts.ts`, key `wordshift_share_prompts`) mirrors this exactly for growth rather than revenue: a single one-time celebratory invite to open the `ShareResultModal` at the player's first genuine peak (first flawless win OR first phase transition, whichever lands first), suppressed during onboarding and forever after firing; also device-local (a fresh device may re-earn it), cleared in Reset All.

**Never:** energy/lives, loot boxes, pay-to-skip-phases, forced ads, paywalled animals. (Amber/hint packs **are** sold as of the revenue pass, but stay convenience-only: amber never feeds phase progress and hints never bypass the star cost — the *progression* line is the hard constraint, not the currency sale.)
