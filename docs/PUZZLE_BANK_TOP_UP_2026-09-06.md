## Generator and hygiene fixes

- Expert and explicit Lexicon searches now actually use the reviewed advanced vocabulary they are allowed to require. Common and advanced insertion caches are separate. Whole asynchronous searches are serialized so vocabulary, phase and rarity context cannot leak between overlapping calls.
- Reverse search filters capped return intermediates, locks only the received tile position (not every copy of its letter), prefilters impossible receiving words, and proves exact sampled descents before searching their return. Its intended two-second improvement window now starts when a valid chain is found; the old condition could spend about 23 seconds retrying already valid low-score chains. Both reverse solvers validate every remainder, including unique-letter removals; chosen alternate placements also rewrite forward hint words and explanations. Runtime variant compatibility uses the shipped gameplay validator, independent of temporary generator search context.
- Bounded one- and two-row mutations reuse proved reverse transfer geometry from the current pool and its common/rare counterpart, replay both legs with cumulative locks, rebuild hint metadata, and then pass every unchanged rarity, cap, monotony and shipped-route gate. Copied sibling chains are excluded. This expanded the scarce Lexicon Reverse Expert pool without hand-editing records.
- Hard/Expert Lexicon offline searches prefer rare but fair seeds and a stronger rarity score. Their existing featured-rank ceilings, mean-rarity floors, word caps and route gates remain intact.
- New Double Shift candidates reject blocked first-removal/first-drop strings. Eight common curse-word forms absent from the historical dictionary were added to the explicit blocklist because a temporary string can still spell them. The pre-install purge removed three affected live boards; staging also caught one Lexicon Double Shift Hard candidate generated before the blocklist expansion, which was excluded by the gated seed-preparation tool and replaced before installation. No dictionary entry was removed.
- Gated acceptance also checks aggregate letter monotony. It can dilute an inherited spike while refusing additions that would exceed the retained 30% limits.
- Top-up preparation seeds only eligible, solved live or staged boards. Vocabulary fingerprints prevent stale checkpoint counts or stale sidecar swaps from bypassing review. Drivers use `npm test`, bounded slices, resumable checkpoints and a default 650 MB heap.

## Review and reproduction

Every target was staged, audited and reviewed with `swapGatedBanks.mjs 100 <family> <difficulty> --dry-run` before the official targeted swap. The mandatory profanity purge and full audits were repeated after installation. There were no manual edits to generated bank records and no legacy generator run.

From `mobile/`:

```sh
node --max-old-space-size=180 scripts/tools/auditVocabulary.mjs --branching --minimum-eligible=100
node --max-old-space-size=180 scripts/tools/auditBankRoutes.mjs
node scripts/tools/updateDailyBoardVersion.mjs --check
npm test -- --no-coverage --runInBand --testPathPattern='bank|Bank|Vocabulary|vocabularyHygiene|generatorVocabulary|gatedTooling|puzzleContentPolicy'
```

The current daily cohort is `daily_v2_e8f99141efc9d9c6`, derived from ordered bank content, dictionary/policy data and the daily selection/date code, so future board changes receive a different leaderboard identity. Existing saved daily boards retain their recorded cohort.
